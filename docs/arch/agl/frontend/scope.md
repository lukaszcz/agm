# AgL Name Resolution

The scope pass resolves every name in the program, over the whole module graph, and publishes immutable side tables, including each module's reachable declaration identities. Typecheck consumes them and never re-resolves; scope in turn never guesses — a module's own declaration wins, and two or more distinct contributed declarations where a spelling is decided are an ambiguity reported at that use.

## Full-Path Lookup

A scope path is part of a declaration's name; a `scope` region is not an entity, and regions of one path, in one module or several, combine. One lookup (`scope/lookup.py`) decides every spelling in every position; the position picks the kind (`LookupKind`: type, value, constructor), and a qualified spelling finding only another kind is a `Misfit`, which the position reports. A spelling `p` written in `scope S1::S2` is tried at `S1::S2::p`, then `S1::p`, then `p` (`lookup_steps`); each step reads the module's own declarations at that full path plus the contributions (imports, uses, the prelude, injected enum members) anchored at or above it, and the first step selecting anything decides (`_decided`): the own declaration, else one distinct declaration, else an `AmbiguousQualificationError` naming every origin. Distinctness is by declaration identity (`PathSources.denotes`), so an alias and its target, two aliases of one denoted type, or two routes to one declaration count once. `::p` reads own declarations and root inline constructors, with visible builtin prelude constructors as fallback, and a module route (`lib::p`, `/lib::p`) that module's exports alone — never the reader's own declarations beneath its types. Only a scope path, type, alias, or module route qualifies; a type in a prefix reads on through its member table, a path beneath an alias reads literally (below), and a segment's type arguments are legal only where the next segment is the selected generic type's inline member. A miss reports, in order, `HiddenMemberError`, `UnknownMemberError` of the longest visible prefix, then `UnknownQualifierError`. `lookup_declared` reads a declaring path (a method receiver, a scope-path recording) at its parent step alone.

The lookup owns order and verdicts; `PathSources` is what it reads. `ModuleSources` (`scope/sources.py`) implements it for one module: own declarations and constructors by full path, import contributions, enum members injected at their enum's own step (imported enums too), and the declaration each own scope path names, recorded shorter-first and re-read until stable. Readings of a static-root module are kept once its own types are resolved (resolving a type reads only its declaring module); a read during a use's own read is not kept, and other modules (REPL and `-c` entries) read live. `UseReader` (`scope/uses.py`) records each `use` on its region and re-reads its target by whole path on every read, seeing only the uses written before it; nothing is snapshotted.

Every verdict is recorded once: bindings in `resolution`, and each qualified chain's or named type's selection in `owner_declarations` by node id (`DeclarationSelection`, or `OwnerMemberSelection` for an owner's inline member). Typecheck, match compilation, lowering, and the REPL only read these; the REPL turns a rejection into data at one boundary (`_static_verdict` in `repl/session.py`).

## Declarations and Aliases

Resolution runs in three phases over every module of the program: constructing a module's resolver (`_prepare`) checks item placement, collects its declarations, and resolves its `use` and region-import headers; `collect` gathers constructor candidates and root bindings once every module is constructed, since type owners answer from all headers and a path read through another module's alias reads that module's tables; `resolve` then walks the bodies in graph order. Header diagnostics of every module therefore precede body diagnostics of any. Ordinary bindings and parameters are installed by an ordered walk that preserves textual visibility and are nearer than any lookup step. A module-level `let`/`var` of a static-root module (every file-backed module: its initializers are constant, so declaration order cannot matter) is pre-populated the same way a `def` is; everywhere else — the REPL, an inline `-c` entry — it keeps the ordered walk's textual visibility. Either way, its name claims its scope path in the same declaration registry a `def`, type, or named scope does, so a collision is rejected regardless of declaration order or module kind. `scope/bindings.py` is the small leaf over the finished resolution table that answers which of a module's own static bindings an expression reads; constant classification and initializer ordering both ask it. Type and value lookups are independent, so a type-only contribution never hides a value.

Every declaration and region is at its written path. An alias declares no scope: declaring beneath a name the module itself declares as an alias — a type alias or a `use` renaming a type — is an `AglScopeError` in either order (`_reject_declaring_beneath_aliases`, `_reject_declaring_beneath_type_renames`; across REPL entries `reject_declaring_beneath_retained`), and a method receiver selecting a type through any alias is rejected (`_reject_alias_receiver`). Beneath an imported alias name, own declarations stand at their written path.

A path beneath an alias reads literally: `Geo::x` with `type Geo = Base` is `Base::x` with the target as written, looked up in the alias's region and module (`ModuleSources.projected` → `_beneath_alias` → `read_through`/`lookup_through`). The site's imports, uses, and `hiding` therefore apply, and an importer's own declarations are never reached through another module's alias. `target_steps` fixes the steps the target is read at; a target leading with a module route, or a reading chain anchored by `::` or a route, reads only that root or route (`_reach`). A re-entrant read of the same alias path reaches nothing more. Re-exports through an alias read the exporting module's exports beneath the target (`exported_through`, `exported_beneath`); hiding an alias removes what a read beneath it reaches (`reached_beneath`, `removed_with`, carried into export settling by `Denotations` in `scope/program.py`).

Inline enum members are nominal record declarations beneath their enum's scope. Every constructor reference resolves to a canonical `ConstructorRef` (module, scope path, terminal name, declaration identity); spellings are never identity.

`TypeOwnerIndex` (`scope/type_owners.py`) holds one `TypeOwner` per type path: an enum owns only its inline members; an alias owns the member table of the declaration its target selects at the alias's own declaration (`AliasTargets`), minus the members a `hiding` there removes (`type_names.member_chain` spells a target path for the one lookup). An alias renaming a declaration is that declaration; any other is classified by its normalized denoted type (`denotation`), so an applied alias (`Box[int]`) is distinct from the generic, while a structural alias or one passing a type parameter through reaches no paths. Scope publishes each enum's referenced member names and each alias's hidden paths; typecheck registers them rather than recomputing them, and reads hidden and referenced members through the shared `owner_member_selection` (`scope/type_names.py`).

Constructor candidates are derived from the module's current type owners (`owned_constructors`, `injected_members`): a record, exception, or constructible alias in its declaring scope, inline members at their enum's step, each also bare at the root; an enum injects its referenced records while each is still the declaration at its path. A REPL entry derives them from the retained owners plus its own declarations, minus the paths it redeclares, so entry grouping never changes the result.

Values, patterns, and `is` tests decide a qualified `Owner::Name` through the same lookup (`_select_qualified`). A module qualifier alone (`mylib::Red`, `::Red`) injects its root enums' inline members only where the step finds nothing of the position's kind under that name. Owner-table refusals (a referenced member spelled through an owner, `ReferencedMemberError`; a hidden one) travel with the reading (`Reading.refusals`), so every position reports them alike. `AmbiguousQualificationError` is built only through `for_origins`, rendering structured origins (imported, `use`-contributed, declared); its `AmbiguousConstructorError` subclass adds a `repair` spelling that resolves where written.

Type names bind no value: a value name that finds no binding but spells a visible type reports `type_name_not_a_value`, as typecheck does. A record or exception accepts its own name or any alias name on its chain as a member (`Point::Point`, `P::P`); a structural alias qualifies no constructor.

Scope keeps every pattern and `is` spelling's visible candidate set, and typecheck selects from the matched nominal type, never outside it (`_select_enum_member`, `_record_constructor_pattern_ref`, `_constructs_record`, `_related_exception` in `typecheck/checker.py`). A bare spelling with no visible candidate is a `NoVisibleConstructorError` in scope. A spelling qualified by a plain scope or a module qualifier is published in `scope_qualified_spellings`: its candidates are complete, so typecheck rejects any other against the matched type; a type owner's miss is left to typecheck.

A record, enum-member, or exception field's `= expr` default resolves like a function parameter default: an ordinary expression in the declaring type's own lexical layer.

## Imports and `use`

An import contributes a module's exports, by declaration identity, minus what its `hiding` removes; `hiding` and item lists may name paths through an alias, and are validated against the exports eagerly (`validate_import_items` in `scope/imports.py`). Import tails and `use` add bare names to the region that declares them without narrowing qualified access, and a region's uses are not part of its qualified surface; `use X::*` combines every scope at that path. `use` reads only already nameable paths and never loads a module. Exports and re-exports are settled per import SCC to a fixpoint before any importer reads them, items through an alias included, with the same collision rules as local names. Loading-level rules are in [modules.md](../modules.md).

## Classification

Scope classifies what typecheck will type: a built-in call is recognized by resolving its callee to a `builtin def` declaration, never by spelling, while a runtime built-in outside call position remains an ordinary resolved function reference. Most builtin call names are additionally reserved in bare position (`BUILTIN_CALL_NAMES`), forcing a bare spelling to the builtin even over an in-scope function of that name; `parse`/`try-parse` (`std/value`) are classified through a second, non-reserved name→kind map instead, so `std/json`'s and `std/toml`'s own declarations of those names stay reachable. Binding references retain builtin and method provenance across import aliases so typecheck can distinguish free, static, and unbound-method values. The link-time `resource` form stays call-only because its path must remain visible as a source literal. A `self`-receiver `def` attaches to the type its full path selects at the path's parent step (`lookup_declared`), with no outward fallback; a receiver through an alias is rejected, and only a built-in head takes type arguments; scope classifies built-in receivers (`BuiltinMethodReceiver`) and typecheck reads the result. Each module's resolution publishes the declarations reachable through its routes. `builtin var` bindings are host-backed values, of which only root `std/config` bindings are engine settings. A simple static `let`/`var` is exported like a declaration, and a cross-module reference to it keeps `var`'s mutability. Index and field assignment receivers resolve as ordinary reads; typecheck owns container, field, and mutability rules. A declaration's `{…}` constraint block is checked here: each constrained name must be one of its (or, for a method, its receiver's) type parameters, with no duplicate or redundant pairing.

## Operators

A user operator is a name. The parser leaves a chain containing one as a `RawInfixChain` ([syntax.md](syntax.md)); the body walk resolves each operator as a callee and groups the chain with the fixity the selected declaration's module declares for that name (`_resolve_infix_chain`, `_operator_fixity`, `_fixity_of`). A module's fixities (`_own_fixities`) read relative priorities like an operator at the root (`_priority_base`); one naming nothing the module declares is rejected (`_reject_fixities_declaring_nothing`). `resolve` rewrites every chain once (`replace_infix_chains` in `infix.py`) before attribute recognition, so `ModuleResolution.program` is the grouped program; `ModuleResolution.fixities` carries the module's own fixities, which the REPL threads across entries.

## Attribute Recognition

The parser keeps every `@attribute` verbatim; scope is where one acquires meaning. A single walk over the declarations checks each attribute against the catalog in `agl/attributes.py` — the name exists, the declaration is an admitted target, the arguments match the declared schema (including the spelling an option attribute's schema narrows its text to), the attribute is neither repeated nor contradicted — and hands the surviving attributes to small per-attribute fact builders that write typed side-table entries. Recognizing a further attribute adds a fact builder, never another traversal.

A text argument is a constant expression, folded by `syntax/module_constants.py` ([syntax.md](syntax.md)) before any spelling rule sees it, so every fact builder still reads plain text. The walk tracks the scope path of the static item it is inside and folds from there; the fold is AST-only, which is what keeps the parse-only package scan on the same implementation and confines a reference to the declaring module.

The fact built from the `@arg-*` attributes is `param_zones`, the zone of every parameter and field keyed by its node id: an entry's own attribute wins over its declaration's default, which wins over the form's default (standard, but named-only for a `program def`). A `self` receiver is positional-only and admits no zone attribute, and an entry list written out of zone order is an error here rather than in the parser. Typecheck builds every parameter and constructor-field list from this table; the AST itself carries no zone.

The fact built from `@extern-name` is `extern_names`, every `extern def`'s Python companion name keyed by its node id: the attribute's argument, or the declared name verbatim. Scope applies the Python-identifier rule to that effective name, so a name Python could not define is rejected here with the attribute as the remedy, and keys companion-symbol uniqueness on it too — a module's externs share one companion, wherever in the module they are declared, so no two of them may map to the same effective name. Lowering and companion resolution read the table; no name is derived from the AST or mangled.

The fact built from `@name` and `@json-name` is `external_names`, an `ExternalName` per field, enum member, or record declaration keyed by node id. Scope only validates each attribute's own text (`@name` must be a plain AgL identifier, `@json-name` any non-empty text but `"$case"`); collisions among sibling fields or enum members are a typecheck concern, since they need full type-table visibility across exception base chains and cross-module enum members.

The facts built from `@param`, the `@opt-*` attributes, and `@doc` are `params`, `program_options`, and `docs`. `params` holds one `ProgramOptionSpec` per static root or scope-region `let`/`var` marked `@param`, keyed by its binding node id; `program_options` holds the same presentation shape per `program def` parameter. Each spec carries the external name a host addresses it by (`@opt-name`, else the declared name) plus its short spelling, environment variable, metavar, hidden flag, and help text. Those shapes a host has to spell — a short option is one ASCII letter, an option name a flag word of letters, digits and hyphens that a host can also negate — are the catalog's, checked with every other argument rule; scope additionally rejects the attributes that presuppose a name (`@opt-name`, `@opt-short`, `@opt-env`, `@opt-hidden`) on a positional-only program parameter. `docs` holds the `@doc` text of every declaration carrying one, parameters and fields included, keyed by that declaration's node id. Program discovery ([hosting.md](../hosting.md)) hands program and parameter facts to the host; type building retains nominal declaration prose on the identity-keyed `TypeDef` metadata used by schema derivation.

The fact built from `@command` is `command_registrations`, one command path per `program def` that registers itself as a package command, keyed by node id; the path answers to the same rule a manifest command path does, which the catalog checks against the CLI's own reserved surface. A command carries no prose of its own — the program's `@doc` is filed in `docs` like every other declaration's, and the package domain pairs the two. The table is published like any other, but the package domain does not read it: registration discovery runs over a bare parse, and calls `recognize_program_registration` to apply this same recognition to one declaration without a scope pass, taking the program's documentation and registered path together ([packages.md](../../packages.md)). Resolving a package module still validates its `@command` attributes, as it does every other.

## Code Entry Points

- `src/agm/agl/scope/lookup.py` — full-path lookup: steps, anchors, decision, misses.
- `src/agm/agl/scope/sources.py` — `ModuleSources`, what one module's lookups read; `scope/uses.py` — `UseReader`, reading `use` targets.
- `src/agm/agl/scope/resolver.py` — declaration collection, the ordered walk, receiver and built-in classification.
- `src/agm/agl/scope/imports.py` — import contribution environments and item validation.
- `src/agm/agl/scope/program.py` — export maps, per-SCC re-export settling (`_converge`, `Denotations`), cross-module resolution.
- `src/agm/agl/scope/type_owners.py` — `TypeOwnerIndex`: type owners, alias targets and identity, constructor candidates.
- `src/agm/agl/infix.py` — operator fixity, chain grouping, and the rewrite replacing raw chains.
- `src/agm/agl/scope/type_names.py` — alias member chains and the shared member selection.
- `src/agm/agl/scope/attributes.py` — attribute recognition against the catalog and the fact builders it feeds.
- `src/agm/agl/scope/bindings.py` — a module's own static bindings and which of them an expression reads.
- `src/agm/agl/scope/symbols.py` — builtin call names, symbol kinds, `ConstructorRef`, `TypeOwner`, `ReceiverOwner`, selections, scope errors, and `AttributeFacts`.
- Tests: `tests/test_agl_scope*.py`, `test_agl_namespace_*.py`, `test_agl_qualifier_*.py`, `test_agl_full_path_lookup.py`, `test_agl_*alias*.py`, `test_agl_operator_names.py`, over the qualifier harness `tests/agl/qualifier_support.py` ([testing.md](../../testing.md)).
