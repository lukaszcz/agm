# AgL Name Resolution

The scope pass resolves every name in the program, over the whole module graph, and publishes immutable side tables, including each module's reachable declaration identities. Typecheck consumes them and never re-resolves; scope in turn never guesses — any ambiguous bare or qualified route is a static error.

## Namespaces and Scopes

Resolution runs in two phases over every module of the program: constructing a module's resolver collects its declarations and resolves its `use` and region-import headers, then `resolve` pre-populates constructors and walks the bodies, since which constructors a header contributes depends on type owners that other modules' headers decide. Header diagnostics of every module therefore precede body diagnostics of any. Collection builds module-root and named-scope layers pre-populated with static declarations and constructors; ordinary bindings and parameters are then installed by an ordered walk that preserves textual visibility. A module-level `let`/`var` of a static-root module (every file-backed module: its initializers are constant, so declaration order cannot matter) is pre-populated the same way a `def` is, ahead of the ordered walk; everywhere else — the REPL, an inline `-c` entry — it keeps the ordered walk's textual visibility. Either way, its name claims its scope path in the same declaration registry a `def`, type, or named scope does, so a collision is rejected regardless of declaration order or module kind. `scope/bindings.py` is the small leaf over the finished resolution table that answers which of a module's own static bindings an expression reads; constant classification and initializer ordering both ask it. Named-scope declarations are addressed by their full `::` path, and repeated `scope` regions extend one namespace. Type and value namespaces are looked up independently through lexical layers, so a type-only contribution never hides an outer value.

Inline enum members are nominal record declarations beneath their enum's scope. Every constructor reference resolves to a canonical `ConstructorRef` (module, scope path, terminal name, declaration identity); spellings are never identity.

Type paths select constructors through `TypeOwnerIndex` (`scope/type_owners.py`), one `TypeOwner` per path: an enum owns only its inline members; an alias selects what its target type name selects in an annotation at the alias's declaration (the shared selection in `scope/type_names.py`, which typecheck also uses), minus the members that target's import or `use` hides. Local, scope-region, imported, `use`-selected, and REPL-retained paths select alike. Scope publishes each enum's referenced member names and each alias's hidden members; typecheck registers them rather than recomputing them.

Constructor candidates are derived from the module's current type owners (`owned_constructors`): a record, exception, or constructible alias in its declaring scope, inline members in their enum's scope, each also bare at the root; a root enum injects its referenced records bare while each is still the declaration at its path. A REPL entry derives them from the retained owners plus its own declarations, minus the paths it redeclares and the member scopes a redeclared enum no longer declares, so entry grouping never changes the result.

Values, patterns, and `is` tests select a qualified `Owner::Name` in one order: a `use`-contributed owner, a local scope or type path, an imported atom naming a constructor (`_cross_module_constructor`), then an imported type owner (`_qualified_constructor_candidates` in `scope/resolver.py`). A module qualifier alone (`mylib::Red`, `::Red`) selects from the module's surface: a root constructor of that name, else the single inline member of its root enums, re-exported ones included (`_module_surface_constructor`, `_route_injected_members`). Failures are reported alike in every position: `ReferencedMemberError` (`diagnostics.py`) for an owner spelling of a referenced member; a hidden-member error for a member hidden by its import, through its owner or an alias spelled through that import (`_reject_hidden_member`); the scope's unknown-member error for a plain scope lacking the name; `RouteClashError` for a leading segment naming both a local scope or type and a module route that contributes the name, or a plain scope not declaring it (`_check_local_scope_route_ambiguity`); and `AmbiguousConstructorError`, whose `repair` resolves where written — through the written qualifier, or for a bare spelling through a bare owner name that selects the imported owner at the use, else the shortest unique route (`route_spelling` in `scope/imports.py`).

Type names bind no value: bare lookup skips a named-scope type with no constructor of its own, so a type never hides a value, and a value name that finds no binding but spells a visible type reports `type_name_not_a_value`, as typecheck does. `Alias::Name` publishes the alias's own `ConstructorRef`; a record or exception accepts its own name or any alias name on the chain; a structural alias qualifies no constructor.

Scope keeps every pattern and `is` spelling's visible candidate set, and typecheck selects from the matched nominal type, never outside it (`_select_enum_member`, `_record_constructor_pattern_ref`, `_constructs_record`, `_related_exception` in `typecheck/checker.py`). A bare spelling with no visible candidate is a `NoVisibleConstructorError` in scope. A spelling qualified by a local plain scope or a module qualifier is published in `scope_qualified_spellings`: its candidates are complete, so typecheck rejects any other against the matched type; a type owner's miss is left to typecheck.

## Imports and `use`

An import contributes a module's full public qualified surface minus what its `hiding` clause removes. Import tails and `use` declarations add bare names to the lexical region that declares them without narrowing qualified access; `use` selects from routes that are already nameable and never loads a module. Exports and re-exports are resolved program-wide with the same collision rules as local names; routes to one declaration deduplicate, distinct origins stay ambiguous. Loading-level rules are in [modules.md](../modules.md).

## Classification

Scope classifies what typecheck will type: a built-in call is recognized by resolving its callee to a `builtin def` declaration, never by spelling, while a runtime built-in outside call position remains an ordinary resolved function reference. Most builtin call names are additionally reserved in bare position (`BUILTIN_CALL_NAMES`), forcing a bare spelling to the builtin even over an in-scope function of that name; `parse`/`try-parse` (`std/value`) are classified through a second, non-reserved name→kind map instead, so `std/json`'s and `std/toml`'s own declarations of those names stay reachable. Binding references retain builtin and method provenance across import aliases so typecheck can distinguish free, static, and unbound-method values. The link-time `resource` form stays call-only because its path must remain visible as a source literal. During the ordered lexical walk, a `self`-receiver `def` resolves to a `ReceiverOwner` through the same nearest bare-contribution and constructor precedence as ordinary names, while builtin receiver spellings are recognized independently of any enclosing named region and retain their declaring module. Each module's resolution publishes the declarations reachable through its routes. `builtin var` bindings are host-backed values, of which only root `std/config` bindings are engine settings. A simple static `let`/`var` is exported like a declaration, and a cross-module reference to it keeps `var`'s mutability. Index and field assignment receivers resolve as ordinary reads; typecheck owns container, field, and mutability rules. A declaration's `{…}` constraint block is checked here: each constrained name must be one of its (or, for a method, its receiver's) type parameters, with no duplicate or redundant pairing.

## Attribute Recognition

The parser keeps every `@attribute` verbatim; scope is where one acquires meaning. A single walk over the declarations checks each attribute against the catalog in `agl/attributes.py` — the name exists, the declaration is an admitted target, the arguments match the declared schema (including the spelling an option attribute's schema narrows its text to), the attribute is neither repeated nor contradicted — and hands the surviving attributes to small per-attribute fact builders that write typed side-table entries. Recognizing a further attribute adds a fact builder, never another traversal.

A text argument is a constant expression, folded by `syntax/module_constants.py` ([syntax.md](syntax.md)) before any spelling rule sees it, so every fact builder still reads plain text. The walk tracks the scope path of the static item it is inside and folds from there; the fold is AST-only, which is what keeps the parse-only package scan on the same implementation and confines a reference to the declaring module.

The fact built from the `@arg-*` attributes is `param_zones`, the zone of every parameter and field keyed by its node id: an entry's own attribute wins over its declaration's default, which wins over the form's default (standard, but named-only for a `program def`). A `self` receiver is positional-only and admits no zone attribute, and an entry list written out of zone order is an error here rather than in the parser. Typecheck builds every parameter and constructor-field list from this table; the AST itself carries no zone.

The fact built from `@extern-name` is `extern_names`, every `extern def`'s Python companion name keyed by its node id: the attribute's argument, or the declared name verbatim. Scope applies the Python-identifier rule to that effective name, so a name Python could not define is rejected here with the attribute as the remedy, and keys companion-symbol uniqueness on it too — a module's externs share one companion, wherever in the module they are declared, so no two of them may map to the same effective name. Lowering and companion resolution read the table; no name is derived from the AST or mangled.

The fact built from `@name` and `@json-name` is `external_names`, an `ExternalName` per field, enum member, or record declaration keyed by node id. Scope only validates each attribute's own text (`@name` must be a plain AgL identifier, `@json-name` any non-empty text but `"$case"`); collisions among sibling fields or enum members are a typecheck concern, since they need full type-table visibility across exception base chains and cross-module enum members.

The facts built from `@param`, the `@opt-*` attributes, and `@doc` are `params`, `program_options`, and `docs`. `params` holds one `ProgramOptionSpec` per static root or scope-region `let`/`var` marked `@param`, keyed by its binding node id; `program_options` holds the same presentation shape per `program def` parameter. Each spec carries the external name a host addresses it by (`@opt-name`, else the declared name) plus its short spelling, environment variable, metavar, hidden flag, and help text. Those shapes a host has to spell — a short option is one ASCII letter, an option name a flag word of letters, digits and hyphens that a host can also negate — are the catalog's, checked with every other argument rule; scope additionally rejects the attributes that presuppose a name (`@opt-name`, `@opt-short`, `@opt-env`, `@opt-hidden`) on a positional-only program parameter. `docs` holds the `@doc` text of every declaration carrying one, parameters and fields included, keyed by that declaration's node id. Program discovery ([hosting.md](../hosting.md)) hands program and parameter facts to the host; type building retains nominal declaration prose on the identity-keyed `TypeDef` metadata used by schema derivation.

The fact built from `@command` is `command_registrations`, one command path per `program def` that registers itself as a package command, keyed by node id; the path answers to the same rule a manifest command path does, which the catalog checks against the CLI's own reserved surface. A command carries no prose of its own — the program's `@doc` is filed in `docs` like every other declaration's, and the package domain pairs the two. The table is published like any other, but the package domain does not read it: registration discovery runs over a bare parse, and calls `recognize_program_registration` to apply this same recognition to one declaration without a scope pass, taking the program's documentation and registered path together ([packages.md](../../packages.md)). Resolving a package module still validates its `@command` attributes, as it does every other.

## Code Entry Points

- `src/agm/agl/scope/attributes.py` — attribute recognition against the catalog and the fact builders it feeds.
- `src/agm/agl/scope/resolver.py` — declaration collection, `use` selection, regional bare contributions.
- `src/agm/agl/scope/imports.py` — import contribution environments and qualified resolution.
- `src/agm/agl/scope/program.py` — export maps, re-exports, cross-module resolution.
- `src/agm/agl/scope/type_owners.py` — `TypeOwnerIndex`, the alias walker behind owner-qualified constructors.
- `src/agm/agl/scope/type_names.py` — which declarations a type name selects where it is written, shared by scope and typecheck.
- `src/agm/agl/scope/bindings.py` — a module's own static bindings and which of them an expression reads.
- `src/agm/agl/scope/symbols.py` — builtin call names, symbol kinds, `ConstructorRef`, `TypeOwner`, `ReceiverOwner`, and `AttributeFacts`, the recognized-attribute tables the resolution carries.
- Tests: `tests/test_agl_scope*.py`, `test_agl_namespace_*.py`, `test_agl_qualifier_*.py`.
