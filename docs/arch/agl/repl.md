# AgL REPL and Program Hosting

Two commands host AgL programs: `agm exec` runs a whole program, and `agm repl` evaluates entries one at a time. Both run the same pipeline ([index.md](index.md)); they differ in how the program is supplied and how parameters, agents, and configuration are wired around it. This document covers that host-facing surface.

## Incremental REPL Session

The REPL is a UI-free incremental driver that runs the full pipeline one entry at a time against two persistent images: the static session environment and the linked IR/host image. Node ids stay globally unique across entries, new references fall through to prior session bindings, retained named scope layers keep path-qualified declarations, bindings, and type-kind metadata available, and the retained type environment carries their method registry. A type, a later method declaration, and a later call can therefore span entries; new declarations shadow. Each entry contributes a delta of initializers executed against one persistent base frame, so earlier initializers and host calls are never replayed.

Each evaluated entry still creates a fresh `IrInterpreter`. The shared extern registry keeps a loaded companion module and its ordinary Python globals for the session, but the companion `runtime.state` accessor reaches an interpreter-owned bag through the extern call's `ContextVar`; that bag persists across calls within one entry only. It is not a module global and is discarded when the entry finishes. `:reset` also replaces the registry, so it reloads companions and their module globals on a later import.

A scoped `let`/`var`/`param` retains like a scoped `def` or type: a fresh entry seeds each named scope node's members from the session copy (`src/agm/agl/scope/resolver.py`) and promotion copies completed members back by name, so a same-path redeclaration replaces rather than collides, while same-entry duplicate detection runs against a per-entry registry.
An ordinary retained member still occupies its namespace position: a later
entry may replace it with another member, but cannot reopen that member path as
a nested scope. Replacing a retained parameter with another member also removes
its parameter-inventory metadata.

Every entry is an inference boundary. Before promotion, its unannotated functions use the same disposable candidate-return discovery as a standalone module, then ordinary checking validates the resulting concrete signatures. Only validated concrete signatures and final checked artifacts can enter the session; a static failure promotes neither, so later entries start clean. Runtime failure is deliberately non-transactional: lowering records the source item behind each emitted entry initializer — a scope region is transparent to that indexing, so each of its members is its own promotable item rather than sharing its region's — and promotion maps the initializers the interpreter actually completed back through that record. An entry rejected before any initializer runs — a companion import that fails after lowering, or an evaluator initialization that rejects a declared setting default — promotes nothing and so instead rolls back its whole incremental link delta, but still consumes the parsed node-id range: extern wiring registers the entry's nominal identities before it imports any companion, and the extern registry's nominal classes are insert-only, so reusing those ids would let a later redeclaration inherit the rejected entry's shape. Resource resolution rejected during lowering also restores the whole link delta and returns a source diagnostic; because it has not registered anything with the host, the entry can reuse its node-id range. The REPL never re-predicts which items produce initializers, so a change to what lowering emits cannot silently desynchronize promotion from execution. Pre-installed captureless function closures count as completed even if a later parameter default fails; parameters themselves count only after their own installation succeeds. The completed set is then closed over current-entry runtime references, nominal-type metadata, and imported runtime references to actual library modules in the current compiled graph whose modules initialized completely or were already retained, so a closure is retained only when everything it needs is available too. Host/root builtin identities are not module dependencies. Thus a completed pattern initializer retains all of its selected binders, while an independent completed function closure retains its signatures and binding metadata even when a later call raises. A trailing binder keeps the language's unit block result (or bottom when its initializer exits); a simple binder echoes its stored name, type, and value, while a destructuring `let` echoes its complete matched value and type. Check-only reports bottom for an initializer that always exits. No REPL-only syntax is synthesized, and multi-item entries retain ordinary block discard checking. Redefining a record, enum, or exception mints a fresh declaration identity rather than mutating the existing one, so a redeclaration is supersession, not invalidation: a bare name resolves to the newest declaration going forward, while every retained binding, scope member, and `catch` clause built against an earlier declaration keeps resolving against that declaration — its own fields/variants, its own methods, its own base chain — unaffected by the redeclaration; a redeclaration the entry never promoted leaves the name on the declaration that survived, which reclaims it by re-registering (`docs/agl/reference/types.md`, "Members of nominal types"). An unpromoted declaration's own linked nominal state needs no rollback, for any declaration kind including `builtin`: the link image's nominal state — descriptors and the host-mint table alike — is derived rather than authoritative, since every lowering call rebuilds both from the shared type table, which retains an unpromoted declaration under its own identity exactly as it retains a superseded one — so what takes the declaration out of reach is the type table marking it as never having taken effect (`TypeTable.orphan`), which releases its name and excludes it from every whole-table query about what the session declares, alongside the environment's own type namespace going back to the declaration that survived. Match compilation runs before the check-only early return, so non-exhaustive cases cannot bypass static validation.

Entry parameters are installed before any initializer runs, so their completion is not a function of the initializer frontier. The promotion plan pairs each parameter declaration with the symbol lowering allocated for it and consults the symbols the interpreter actually installed, so a partially installed parameter list promotes exactly the parameters that took effect — and any declaration reading an uninstalled parameter is pruned by the same dependency closure as any other incomplete dependency. A partially failed run also retains each fully initialized imported module whose imported dependencies completed, caching its loaded syntax and marking its linked identities together. Successfully installed params from exactly those modules join the active imported inventory, so a promoted closure keeps both its runtime binding and later config-validation metadata without the module or param being reinstalled; params from an incomplete module never join it.

The REPL uses the program pipeline ([modules.md](modules.md)) by default so it gets the same automatic `std/core` open import as `agm exec`, in each entry and its loaded library modules; `agm repl --no-stdlib` disables that injection throughout every loaded REPL program, including after `:reset`. Library modules are cached and incrementally linked. Fresh default-stdlib sessions in one host process also reuse an unchanged checked bootstrap image from a small per-process LRU cache; normalized source-content changes, missing required extern companions, canonical resolved-module-path changes, root-discovery changes (including new competing modules or wildcard matches), setting overrides, roots, and host capabilities select a fresh image. Imports persist as one retained generation per entry, kept as written so a retained wildcard re-expands each entry and tracks modules added since. Root and region-scoped imports share the same chronological generations. Precedence is by resolved module identity: a later generation replaces every prior root or scoped declaration for each module it names, while declarations for one module in the new entry retain normal batch union semantics and their region placement. Retained scope `open` items are replayed cumulatively in later entries and discarded by `:reset`. This keeps selected-set, suffix, anchored, alias, open, `using`, and `hiding` behavior aligned with batch resolution. User `infixl`/`infixr` fixity also persists by accumulation and replay; promotion resolves relative priorities against the same unambiguous bare-visible assembly table used for the submitted entry, without retaining imported operators as session declarations. Type-focused surfaces (`:type`, check-only echoes) use a REPL-specific type formatter that expands records and enums to declaration-like listings while keeping ordinary echoes compact. An entry is classified by its last item, and a declaration or binding echo names it as the session makes it reachable: a scoped declaration or a shorthand-spelled scoped `let`/`var` by its path-qualified spelling, a scope region by the path it opened. `std/process::exit` instead ends the REPL host: its `SystemExit` is re-raised only after the entry trace receives its final `run_end`, matching batch execution.

## Program Parameters

`param` declarations make a program parameterizable. The pipeline discovers the typed parameter inventory and every `program def` declaration before execution. `agm exec` uses the parameter inventory to expose first-class CLI options and uses file-entry `program def` declaration paths to select a sole entry implicitly or require `-p` when several are declared; a file must declare an entry, while inline source is wrapped in a synthetic one when needed. CLI values override qualified config lookup for every inventory param, then source defaults apply; external values are converted and type-checked before any agent or shell call runs. The selected program's inventory is its declaring module plus transitive import/export dependencies. The REPL has no per-param CLI options: imported params receive qualified config values before installation, and each later import validates config suffixes against the full active imported inventory without reinstalling prior params. Prompt-local params require source defaults.

A param declared inside a named scope region has a short external spelling — what the CLI flag uses when unambiguous — equal to its full path (`Deploy::region`). Parameter discovery retains the declaring module and lowering carries it in `IrParam`, so a module-qualified option selects that declaration when short spellings collide; the option map uses the `--@module::module/path::Deploy::region` form if ordinary positive and boolean-negative qualified flags also collide.

## Agent Values

Each `ask` evaluates an `Agent` enum value and dispatches the argv built from that value. The direct form receives that value through its `agent` parameter; the call-only `Agent::ask` and `Agent::ask-request` methods receive it as their selected receiver. The pipeline prepares a program once (lex, parse, scope) and reuses that prepared object for both parameter discovery and execution. `agm exec` and the REPL seed `std/config::default-agent`; source writes can replace it in program order.

## Engine Settings

The engine settings a program can tune — `default-agent`, `log`, `log-file`, `strict-json`, `max-iters`, `timeout` — are root `builtin var` bindings declared in the standard-library module `std/config`; scoped `std/config` bindings and other standard-library host-backed bindings remain module-, scope-, and name-keyed values rather than engine settings. At session startup, the REPL also snapshots the full process environment once and supplies it as `std/env::environ`; later AgL environment mutations remain in the session only. `src/agm/config/engine_keys.py` is the shared name/kind catalog. A `builtin var` is a body-less, runtime-backed mutable binding whose optional constant initializer is the setting's default: lowering carries that expression as IR and the interpreter evaluates it only when the host provides no seed. Every setting but `default-agent` is seeded as a typed `Value` (`cli_support/engine_seeds.py::build_host_engine_seeds`); an AgL `default-agent` literal (`--agent`/`[exec] default-agent`) instead becomes a `SettingOverride` spliced into `std/config`'s own declaration and resolved by the program's (or, in the REPL, the entry's) own compilation — see [index.md](index.md). `[exec] runner`, a bare host agent command with no AgL syntax of its own, is decoded directly into an `AgentCommand` seed value like any other engine key. In the REPL, `ReplSession.open()` builds the session's initial library image before the console starts: it loads the standard library the same way a first entry would (honoring `--no-stdlib`), applies `setting_overrides` into `std/config` the first time it loads, and resolves and type-checks the result — so a rejected override (unparseable, wrong type, non-constant, or unknown key) is reported before the banner rather than deferred to whichever entry happens to load `std/config` first. `EntryPipeline.load_and_check_program` is the shared graph-build-and-check step both `open()` and `eval_entry` drive; it delegates to the public `pipeline.apply_setting_overrides` (see [index.md](index.md)), which owns both the splice-once apply condition (`std/config` freshly loaded this round vs. already cached vs. never loaded) and the module-cache reconciliation, so the splice fires exactly once per session — normally during `open()`, or on the first entry that loads `std/config` when `--no-stdlib` keeps `open()` from doing so, and again after `:reset`, which clears the module cache (and therefore forces one stdlib reload, by design) but leaves `setting_overrides` itself in force. A graph with no loaded `std/config` is reported only for a `required` override (e.g. `--agent`): `open()` passes `validate_missing_std_config=True` so this is checked up front even when the initial image never loads `std/config`, while an ordinary `eval_entry` call passes `False`, deferring to whichever later entry, if any, first loads it. A non-`required` override (e.g. `[exec] default-agent`) is simply inert whenever `std/config` is absent, at either call site. On success `open()` promotes the loaded modules, the node-id counter, and the type environment into the session's caches, so the first real entry reuses that image instead of recompiling it. Reads and writes route through dedicated IR operations keyed by setting name. The interpreter backs runtime-live settings (`strict-json`, `max-iters`, `timeout`) with live interpreter state, and host-consumed settings with registers. `log` and `log-file` reconfigure live host services; `default-agent` is retained as typed data without a reconfiguration effect. `IrInterpreter.__init__` validates the winning `default-agent` value (seed or declared default) eagerly: an `AgentCommand` whose command text does not shell-split raises `HostConfigurationError`, which `EntryPipeline.eval_entry` catches the same way as a spliced override's own rejection — a per-entry diagnostic, never a process exit.

Because a write is an ordinary positional statement, settings take effect in program order and `agm exec` runs the program in a single phase — there is no separate startup pass. The CLI and config-file layers seed the initial values ([config.md](../config.md)); a declaration's default applies only when they provide no value, and a source write overrides either from its point onward. In the REPL a completed write persists across entries, matching the non-transactional runtime; a key counts as host-controlled by its presence in the seed mapping rather than by its value, so an explicit `strict-json = false` remains a seed rather than falling through to a declared default. `:reset` restores host seeds where present and otherwise the effective declared defaults, applying that one precedence rule to the persisted registers and the live interpreter settings alike.

## Console and Confirmation

The REPL console adds interactivity around the UI-free session: a confirmation wrapper gating live agent calls (confirm/auto modes, Ctrl-C converted into cancellation), syntax highlighting that runs the real lexer and classifies names semantically from declaration context rather than capitalization, parser-driven multiline submission that treats an unterminated string or a line-final raw-tail header as continuation input, and terminal-detected color themes persisted to config.
