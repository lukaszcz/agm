# AgL Lowering and the Execution IR

## Lowering and Linking

Lowering consumes a `MatchCompiledProgram` and emits one linked executable program. It translates expressions directed by expected types, allocates stable program-local identities (symbols, functions, contracts, sources, nominal types), and links modules in the loader's reverse-topological import-SCC order, initializing top-level function closures before ordinary initializers so forward references work. Every module runs its static `let` and `var` initializers; their symbols are allocated with function symbols so a library function reads its module binding dynamically after initialization. Each symbol records its owner — the module for a module-level item, otherwise the function whose body declares it — and closure capture keys on that ownership: a static module binding stays uncaptured because the base frame holds it for the whole run, while a binding a call frame owns is captured, by cell when it is mutable. The synthetic inline entry's own body bindings are function-owned like any other body's, even though they publish a name for `RunResult`, so a lambda in an inline command can read and assign them. Params from every module become module-attributed IR descriptors and are installed before module initialization, so imported functions read the same host-provided per-invocation constants as entry-module code. Type arguments are erased; nominal identity survives as `NominalId`, an opaque handle equal to the declaring checker type's own `decl_id` — the same declaration identity minted during checking (`ir/reserved_nominals.py`, `typecheck/builder.py::_decl_identity`) — with the declaring module, scope path, and declared name carried on the linked `NominalDescriptor` instead of the id, and shapes, including declaration-order record-field mutability, resolved through the shared `TypeTable` from checking. Enum member layouts come from their record definitions. Construction preserves the member record's nominal identity: enum-typed static slots still determine codecs and case alternatives, while runtime members are their own `RecordValue`s, never enum wrappers. The linked enum descriptor retains terminal member names for JSON and FFI interoperation. Display names and schema `$defs` are derived at the execution boundary, so root-type schema names remain stable while scoped types remain distinct. `ask` and `ask-request` lower their agent operand as an ordinary expression; an omitted argument lowers to `IrBuiltinLoad("default-agent")`. The evaluator therefore receives an `Agent` member `RecordValue`, rather than a contextual agent-name sentinel or enum wrapper. A scoped function's body is lowered with the type environment re-entered into its declaring scope, so its sibling references resolve as the declaration site sees them; functions stay unpublished from `RunResult` bindings, and a `def`'s symbol is erased rather than following the binding rule below. A scoped `let`, `var`, or `param` instead publishes under its full path spelling (`scoped_public_name`, `syntax/nodes.py`), the same spelling a reader outside its scope would write, so two same-named bindings at different paths — or a same-named binding and type — stay distinguishable in a run's reported bindings and in REPL echo; internal symbol identity stays the structured declaration node id regardless. Fieldless constructor references lower directly to nominal record construction; field-bearing references lower to callable constructor values, while direct calls use their independently checked constructor-call route. Lowering reads the checker's side tables — argument bindings, parameter types, output contracts — rather than re-binding or re-inferring; that is what keeps the IR and evaluator typeless.

Lowering emits each module's initializer sequence through one shared walk — function closures first, then the remaining items in source order — and records, for each emitted initializer, its own source item. A scope region is transparent to this indexing exactly as it is to the walk itself: each of the region's members gets its own index rather than sharing the region's, so a member completes and promotes independently of its siblings instead of a region acting as one all-or-nothing declaration group. That mapping is the lowering layer's published answer to "which declaration does this initializer complete"; no later pass re-derives it from the AST.

A checker-selected direct ordinary method call lowers to an `IrDirectCall` with the receiver as its first argument, avoiding a bound closure. `resource` and `resource-dir` are resolved while linking against the declaring module's recorded filesystem anchor (its source directory, or its owning package root) and lower to an absolute-path `IrResource`; a module with no anchor (it has no backing file) and missing or escaping targets stop linking before evaluation. A selected builtin method call instead reuses its builtin lowering route, passing the receiver as the `Agent` operand to the existing `IrAsk` or `IrAskRequest`; it adds no IR node or evaluator dispatch path. An ordinary selected method member in value position reuses partial-application closure lowering: it captures the receiver once and calls the declared function with that capture followed by the closure arguments. Builtin methods are call-only and are rejected before lowering.

Case and destructuring immutable-let lowering traverse the same compiled decision DAG and occurrence ledger. Refutable nominal-member and literal choices remain `IrCase` switches keyed directly by member-record identity; singleton records and singleton-enum decisions instead project only the child's demanded fields, in declaration order, before continuing. A binding-mode let captures and coerces its initializer once into a private root occurrence, then materializes only demanded child occurrences. Its leaf immutably initializes one checker-selected symbol per source binder; top-level user binders are public, while root/child occurrences and nested binders are private. A successful binding leaf yields unit, while a bottom initializer never reaches its projections or binders. `IrField` is the single nominal projection contract: its nominal and field identify a validated record or exception field, so decomposition needs neither record case keys nor synthetic enum wrappers.

Decision projections are always exact because the matched constructor establishes the runtime nominal. Source field access records upper-bound mode for exception values, which may hold a derived runtime exception, and exact mode for records; the evaluator can therefore remain independent of nominal hierarchy rules.

Enum-member identity casts retain only the selected member-record nominal in the linked IR. An upcast emits its operand unchanged; its `as?` form evaluates it once and yields `true`. A downcast emits a nominal check whose ordinary form raises `CastError` on mismatch and whose test form yields a boolean. `is` uses the same nominal identity check.

A `let` with a bare-name or `_` pattern lowers directly to a single immutable bind — the same one-instruction shape as `var` for named bindings, or an effect-preserving sequence with no symbol for `_` — because such a pattern cannot fail and introduces at most one name. Only a destructuring `let` goes through the shared decision traversal, which costs a synthetic root symbol and an occurrence ledger. Since simple bindings dominate real programs, this keeps the common binding on the cheapest path in both the lowering walk and the evaluator's hot loop.

## The IR

The IR is a runtime-neutral data model: program-local identities and source locations, a closed family of expression nodes, and a program container holding modules, symbols, functions, program-entry symbols, sources, nominals, contracts, and the module-attributed dry-run inventory. The host operations that parse output — `ask` and `exec` — carry typeless contract requests: codec selection, format instructions, JSON schema, and a decode walk, compiled from checker types during lowering; a target type's decode walk mirrors its JSON Schema `$defs`/`$ref` shape so it hoists and closes exactly where the schema does — a recursive type, or one reached more than once, is emitted once and referenced. Value-to-JSON casts carry an encode walk plus the definitions it references, sharing the same hoisted bodies and carrying enum-member tags, so execution need not infer wire shape from a runtime value. The program also keys every JSON-representable exception field plan by exception nominal, preserving its slot encoding after an exception is handled as a value and re-raised. A growing polymorphic-recursive source uses that same plan with parameterized definitions: a reference supplies one encode schema per type parameter instead of naming a concrete instantiation, while record and enum slots remain distinct, so `$case` tags never come from a global runtime member lookup. `ask-request` carries none, since it builds its request record from its two operands and fixed constants without dispatching or parsing.

`IrAssign` is a plain `var`-cell store (`symbol := value`). An indexed assignment (`target[index] := value`) instead lowers to `IrIndexSet`, which carries the target's *object* expression as a `container` reference rather than a root symbol — under reference semantics the container is mutated in place, so no symbol or `Cell` is needed to reach it. A nested target such as `m["a"]["b"] := v` needs no dedicated multi-step representation: `container` is itself an `IrIndex` reading the inner container by reference, so `IrIndexSet` composes with ordinary index reads instead of carrying its own path.

An array or dict literal in a `json`-expected position lowers straight to `IrMakeJsonArray`/`IrMakeJsonObject`, building the `json` value directly instead of constructing a container and coercing it. Because a container is therefore never implicitly absorbed into `json`, `compile_coercion` (`lower/coercions.py`) only ever emits `IntToDecimal` or a scalar `ToJson`, so an `IrCoerce` node is provably a scalar leaf conversion. `as?` uses the same conversion recipe as `as`, but its evaluator mode reports success as `true` and an ordinary conversion failure or cyclic conversion walk as `false`.

An inline-source host applies the parser's pure syntactic wrapper before static passes. Lowering records its generated unit-returning `main` separately from ordinary entries under a private synthetic symbol, while retaining its AST node-id mapping, and lowers its direct body bindings as reportable bindings; the wrapper may also create an empty body, which lowers to unit. Deep validation confirms that each host-invocable `program def` map entry targets a zero-argument AgL body rather than an extern, that every enum descriptor has unique terminal member names and member-record links, that conversion recipes carry only their selected decode or encode metadata and have well-formed recursive encode bodies, and that the optional synthetic-main symbol resolves through the program-entry map to exactly one marked linked function descriptor. Like match-artifact validation, it re-checks output the lowerer just produced from already-checked source, so it runs only under the AgL self-validation toggle ([testing.md](../../testing.md)) — never in production.
