# AgL Type System and Checking

The semantic type model lives in the `semantics` foundation package and is consumed by the typecheck pass. Alongside scalar, container, record, and enum types it carries what the expression-oriented design needs: a unit type for side-effecting expressions, function types, a bottom type for divergence, and rigid type variables for generics. Solver-internal inference variables are structurally distinct from rigid source variables and never escape checked output.

## Nominal Types Are Handles; the TypeTable Holds Shapes

Record, enum, and exception types are lightweight handles: nominal identity is the declaration a handle names (`decl_id`, an AST node id or a reserved fallback id for a host-known name; see `ir/reserved_nominals.py`), plus type arguments for a generic instantiation, never structure. Every parsed declaration, including `std/core`, retains its AST identity; a reserved identity is used only when no source declaration is loaded. `(module, scope path, name)` is resolution and display metadata, not identity. A later declaration can take a path's name binding without erasing an earlier declaration, whose handles remain valid; an unpromoted incremental declaration is instead marked `TypeTable.orphan` and removed from live queries while remaining derivable for already-linked artifacts.

Handles carry no field or variant data. Each enum member is a record `TypeDef`, scoped below its enum for an inline declaration; an enum definition holds ordered member-record handles, which may also target existing records. `TypeTable.enum_members` and `enum_member_names` instantiate that set, and `record_fields` supplies its payload shape. Runtime construction carries the selected member's record identity directly: a fieldless constructor reference produces that record value, while a field-bearing constructor remains a function value until called. Assignability adds only the directed member-record-to-enum relation at checking and rigid-enum unification boundaries; sibling member records do not acquire a common type without an enum annotation. `std/option` member records may select `Option` methods directly; enum matching and `is` still require an explicit enum binding. Inline-member shells initially capture syntactically mentioned owner parameters, then a pre-body pass resolves aliases and finalizes their arity. Owner-applied inline references substitute through that captured parameter list, and a referenced record may belong to several enums.

All shape lookup goes through the shared `TypeTable` (`semantics/type_table.py`), keyed by declaration identity with a name index for live paths. It is the source of record and enum-member fields, enum membership, exception hierarchy, and methods for typecheck, match compilation, schema derivation, and lowering. The checker selects fields before methods and publishes a specialized receiver-less method in a side table that lowering consumes. Declaration validation indexes each reachable member namespace and rejects field/method collisions, including across exception inheritance. Constructor signatures and field-kind metadata use the same structured owner key; source-facing displays alone use `A::T`.

Built-in and host-contract shapes use the same table. Canonical prelude and exception shapes are fallback definitions; loaded standard-library declarations, including `std/core` and `std/option`, are ordinary source identities and become authoritative. Source builtin shapes are validated against explicit location-independent contracts (`typecheck/builtin_contracts.py`), which compare declaration kind, generics, fields, enum members and payloads, and exception hierarchy without comparing declaration identities or paths. A builtin type or `builtin def` is unique by complete scoped name, so a root contract and a receiver method such as `ask` and `Agent::ask` can coexist. `TypeTable.builtin_declaration` prefers a live non-`std/core` declaration, otherwise the loaded standard declaration, and falls back to the canonical shape only when source provides neither. The same queries derive the host identity table used by lowering, including enum members, so checking and evaluation cannot choose different nominals.

Every host-contract nominal a built-in rule uses — such as `ExecResult`, `AgentRequest`, and `ParsePolicy` — is resolved through `BuiltinCallChecker._builtin_contract_type`; `ask` and `ask-request` use the `agent` field type of the selected `AgentRequest` contract. Host-produced nominal fields use the loaded standard declaration or its fallback, and a coherence check follows those fields recursively through type arguments before a call or catch can expose them. The table accumulates live source declarations across a REPL session just as it does ordinary nominal declarations.

Builtin enum members must be inline, preserving the member identities host-minted values require; ordinary enums may still reference records. `Agent` remains an ordinary data enum for construction, matching, equality, rendering, and conversion.

Because handles resolve regardless of build order, recursive declarations — same-module, mutual, generic, and cross-module — are legal without any acyclicity requirement on the declaration graph.

## Whole-Table Analyses

Recursive types make some questions global. `semantics/analyses.py` answers them over the whole table, cached: **inhabitation** (rejecting a declaration that can never produce a finite value; synthetic inline members are validated through their enclosing enum, while independently declared referenced members remain independently validated), **non-data reachability** (whether `unit` or a function type is reachable from a declaration — named for the fact rather than for either of its two consumers, equality applicability (`comparable_types`) and JSON convertibility (`TypeTable.nominal_is_json_convertible`)), and **finite-schema closure** (whether a type admits a finite JSON schema). The finite-schema result is consulted only at the sites that need a schema — agent/`exec` output targets, fallible cast targets, `param` types, and extern signatures — with a use-site error naming the offending declaration.

`TypeTable.json_representation_obstacle`/`TypeTable.first_non_data_field` (`semantics/type_table.py`) build on non-data reachability to name the culprit field for a rejected `as json` cast, mirroring how `no_finite_schema_message`/`first_infinite_declaration` name the culprit for a finite-schema rejection.

## The Typecheck Pass

The checker selects the concrete behavior the evaluator later relies on and publishes it in checked-program side tables so lowering never re-infers:

- **Built-in typing rules** are dispatched from the resolver's classification — for example `exec` chooses between a structured result, parsed stdout, and an output-discarding unit contract; `ask` takes its result type from context.
- **Casts** are validated against a table of permitted source/target pairs, each classified as total or fallible. `CastKind`/`CastSpec` live in `semantics/types.py`, but the classifier `cast_classification` sits in `semantics/type_table.py` beside `comparable_types` because a `json` target and enum-member identity casts consult declaration shapes, not just the type tree. A member-record-to-enum upcast is a no-op; an enum-to-member downcast selects a declared member and is checked at runtime. `is` likewise requires an enum-typed operand and one of its members, but does not alter either branch's static types. A value-to-`json` cast lowers to a recursive encode plan, so enum tagging follows the source slot type rather than value inspection; a finite static instantiation closure keys that plan's definitions like its JSON Schema `$defs`, while a growing polymorphic-recursive closure uses parameterized declaration templates bound at each reference, retaining static record-versus-enum slot context either way. Three predicates stay distinct: `is_json_convertible` (`as json`), `is_json_shaped` (what may inhabit a `json` slot), and `is_scalar_json_shaped` (what an implicit coercion absorbs).
- **Generics** use rank-1 parametric polymorphism: a generic definition is checked with rigid binding type parameters, and each occurrence is freshly instantiated with flexible variables inside an expression *region* handled by the shared solver (`typecheck/inference.py`). `_` slots remain in the declaration AST as positional metadata but are excluded from binding and instantiation; this leaves declaration-specific consumers free to interpret them later. A lambda may directly widen a member-record body to its expected enum result before the enclosing generic function constraint, allowing that result to select the instantiation without making containers or function parts membership-covariant. Region finalization resolves and validates before publishing, and type arguments are erased after checking. Partial applications are typed as function values with the same machinery.
- **Function headers** are resolved through one shared `typecheck/function_inference.py` seam, whether the candidate component is one import SCC or a single module checked in isolation (the test-only seam over `_check_prepared_module`). Scope-classified method headers construct their positional-only receiver from a nominal owner or from a builtin receiver declaration and its leading generic slots, reject receiver defaults, and validate any receiver annotation. Builtin receiver declarations are restricted to their owning standard-library modules (`std/array`, `std/dict`, `std/text`, `std/json`, or `std/math`) before headers are prepared. Nominal methods publish through the shared `TypeTable`; structural and scalar builtin receiver methods publish through its constructor-keyed table, so selection is ambient wherever the receiver type is available once the owning module is loaded. Ordinary and extern functions may be methods; a `builtin def` may also be a method when its resolved signature matches a supported host contract. The checker routes selected builtin methods through their dedicated call-only builtin rules, so they cannot become function values. Internal signature registration retains each declaration's scope path and node identity, so scoped functions have the same recursion, mutual-reference, and generic inference behavior as root functions. Program checking first collects explicit, builtin, and extern headers plus annotated static-binding types for cross-module constants, then follows derived candidate-inference SCCs from dependencies to consumers. Those retain every loader import edge and add ordering-only edges from consumers to ambient builtin-method modules, making their unannotated method signatures available without widening source scope or changing the loader graph. Each SCC builds a declaration-id-keyed graph for its unannotated functions; a resulting cyclic batch shares provisional results across all of its modules, while an acyclic callee closes before a dependent can consume its function value or call it. Only concrete candidate signatures publish to later module SCCs. Generic candidate edges retain their selected instantiations: recursion is inferred only when every edge preserves the caller's rigid type-parameter vector, while changed instantiations require an explicit result. Candidate common-type evidence from branches, early returns, body tails, and literal elements is normalized before provisional results are solved. Bottom literal evidence is discarded, so it neither conflicts with concrete evidence nor closes an otherwise unresolved candidate; ordinary equality and `int`-to-`decimal` widening remain independent of traversal order. Candidate inference is definition-local: a use-site annotation or argument slot never pins a still-flexible provisional result, so its assignability is validated only by the authoritative recheck and a widening such as `int` into `decimal` is preserved. A call or constructor still contributes its provisional result to the surrounding expression; shape-preserving and fixed-result operations, including membership, can continue through unresolved operands (two unresolved same-family arithmetic operands yield a fresh provisional rather than being forced equal), while unknown field/index shapes do not guess an owner or container. The ordinary checker then rechecks every module body with the complete concrete signature table and is the sole publisher of checked artifacts. Candidate node types, calls, contracts, bindings, and warnings are discarded. Program pre-passes retain named internal signature metadata keyed by declaration node id; public `FunctionSignature` and `FunctionType` remain concrete semantic types.
- **Candidate-validation diagnostics** keep expression- and binding-local inferred-return provenance only while the final checker runs. Calls and first-class function results from candidate signatures seed it; result-dependent generic calls, unannotated lambdas, inferred container literals, generic constructor results, generic pattern fields, and collection-loop elements carry it only when their static result depends on marked input. Successful explicit binding, function, and lambda-result annotations and `as` casts clear it, while their failing boundaries still inspect the marked child. Explicit generic arguments choose an instantiation rather than creating a barrier, so result-dependent argument evidence still propagates, including when the specialized function value is stored and called later. Fixed-result operations and fixed pattern fields also clear it. Failed checks frame only their direct marked participants (including calls, operators, tests, loop headers, and common-type selection); generic solver failures expose structured participating constraints so unrelated arguments cannot add evidence. A frame keeps the ordinary type error as the primary diagnostic at its own source span — so a consumer's explicit annotation is never blamed on the inferred callee — and appends guidance naming the inferred function(s) with their deterministic candidate declaration/evidence locations as related diagnostics. This scratch state is absent from `CheckedModule`, semantic types, schemas, contracts, lowering, and IR.
- **Argument binding and let patterns** go through one routine (`typecheck/arguments.py`) shared by function calls, constructor calls, and constructor patterns; parameter zone markers are resolved to per-parameter kinds in the AST builder, so no later pass sees them. An immutable `let` resolves its complete annotation before checking its RHS once, then uses the same recursive nominal-pattern checker as `case`; `var` remains a single mutable name. The checker resolves every applied record or enum pattern to one source-selected `ConstructorRef`: aliases are transparent, while the selected record must match the scrutinee's full nominal handle. It obtains enum-member or record-field shapes from `TypeTable`, then gives both forms to the shared declaration-order pattern binder, leaving omitted fields as wildcards. The checker publishes each let site's complete matched type, every selected binder's concrete type keyed by its own pattern node, final field-directed bare-pattern classifications, constructor selections, and pattern-slot selections; the let item node remains the match-site key. For each constructor pattern it publishes both the selected source spelling and the concrete nominal owner it resolved to; later passes compare the resolved owner directly instead of replaying candidate narrowing. Scope retains immutable slot references; consumers use `CheckedModule.binding_for` and `constructor_ref_for` for checker-selected meanings rather than rewriting scope tables. Pattern validity and binder typing end here; match compilation alone owns exhaustiveness and irrefutability conclusions.
- **Output contracts** — the schema and format metadata that agent/`exec` calls need — are computed once each region resolves its targets, then compiled into the typeless execution layer ([execution/index.md](../execution/index.md)). Unit calls instead carry an outputless contract: the effect still runs and its successful result is discarded.

Blocks preserve the final item's type. Every earlier bare expression is checked in a unit context, so only unit or bottom values may be discarded there; binders and declarations remain valid intermediate items. A trailing binder therefore yields unit (or bottom when its RHS exits). Loop bodies follow the same unit rule; their bindings remain in scope for the post-body `until` clause, while the pre-body `while` guard sees the loop scope before body bindings. The `_` binder is an explicit discard: its RHS is checked without an annotation or inferred binding type.

An `extern def` shares the body-less builtin-`def` signature path, plus extern-only checks (the name must be a valid Python identifier). Its signature permits AgL function parameters, which cross to the companion as callback proxies; a Python callable returned toward AgL still has no boundary representation and is rejected at runtime. Extern calls typecheck like ordinary calls.

Checked artifacts contain concrete types and no solver state; a leaked flexible variable is a compiler invariant failure. Enforcing that is a self-check gated by the AgL self-validation toggle ([testing.md](../../testing.md)): each inference region asserts closure as it finalizes, and a call after module checking covers every checked-output side table plus the shared whole-program tables. Sealing the type environment is separate and unconditional — it happens once module checking finishes and licenses memoization: namespace-wide enumerations the environment can be asked for repeatedly downstream — own source type names, writable enum-owner forms, and their blocked members — are cached once the declaration namespace is frozen, so later passes simply ask the environment instead of hand-threading results. Seeding the REPL's promoted namespace requires a sealed environment.

## Code Entry Points

- `src/agm/agl/semantics/` — the value model, semantic types, `TypeTable`, whole-table analyses, and exceptions.
- `src/agm/agl/typecheck/` — the checker, built-in typing rules, the inference solver, and argument binding.
- `src/agm/agl/type_schema.py` — compile-time JSON schema, decode, and static encode-plan derivation.
- Tests: `tests/test_agl_typecheck.py`, `tests/test_agl_types.py`, `tests/test_agl_type_table.py`, `tests/test_agl_inference.py`, `tests/test_agl_arguments.py`, `tests/test_agl_typecheck_program.py`.
