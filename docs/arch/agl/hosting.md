# AgL Pipeline and Hosting

`PipelineDriver` (`agl/pipeline.py`) is the public entry point to AgL. It drives parse → scope → typecheck → match compile → lower/link → evaluate, assembles the host environment, and hands every artifact forward so a program compiles and lowers exactly once however often a host resumes it. `agm exec` and registered package commands (through `commands/exec_program.py`), `agm check`, package discipline validation, and the REPL's entry pipeline all sit on it. There is never a second pipeline: anything a host wants compiled is compiled with the program. If `agm exec` or registered-command dispatch must discover a signature while resolving an ambiguous raw tail, `cli_support/program_discovery.py` retains the parsed, prepared, checked, and match-compiled products and passes them into the execution host.

## Host Capabilities

`HostCapabilities` (`agl/capabilities.py`) is a frozen descriptor of the host features that affect checking — shell `exec`, externs, codec kinds. The checker sees descriptors, never runtime implementations, and cached artifacts are keyed by the capabilities they were checked under.

## Programs, Entries, and Parameters

Preparation records every `program def` with its module, scope path, and whether it belongs to the graph's host-selected entry, so a host can select an entry and bind its own value parameters before execution. Entry status is independent of module spelling: a package-owned entry keeps its ordinary package module id, while loose and inline entries use the anonymous sentinel. The selected entry runs after module initialization inside the interpreter's normal boundary. `agm check` uses `check_prepared`, which stops after lowering, so it never binds or validates a selected program's own value parameters — a required parameter with no default is accepted there, unlike under `agm exec`.

`agl/runtime/arguments.py` holds the host-side counterpart for a `program def`'s own value parameters: `ProgramArguments` carries a host's raw positional/named values, and `bind_program_arguments` runs them through the shared zone binder (`agl/semantics/arguments.py`) and decodes each supplied value through its `ParamDecoder`. A structural violation (unknown name, duplicate, positional overflow, a positional-only parameter supplied by name) is reported as a single pre-execution diagnostic; a missing required parameter or a decode failure is reported for every offending parameter, not just the first. `ProgramSignature.fuse` pairs an executable's per-parameter decoders with a declaration's spans and types by name, so the two independent descriptions can never be mismatched by position; `bind_program_arguments_for` is the one place that fuses a `ProgramDeclInfo` with its `ExecutableProgram` and binds, so `PipelineDriver.preflight_arguments` and `commands.exec_program.run` — both of which hold the same two descriptions for a selected program — can never pair them differently. `cli_support/param_surface.py` resolves closure-parameter spellings, and `param_config.py` resolves their program and module routes. `commands.exec_program._bind_host_inputs` is the shared `exec`/registered-command boundary: it parses signature and closure-parameter options, resolves their environment and config routes, reports undeclared leaves for every route, and sends both argument values and module seeds through preflight. A colliding or duplicate flag projection is reported before any value is parsed.

`decode_param_value` (`agl/runtime/arguments.py`) is every host value surface's single decode entry point: `text` crosses verbatim, an `Option[T]` or `Optional[T]` positive value is unwrapped through `OptionSome`'s boxed `value` against `T`'s own field schema, an already-native (JSON-shaped) host value crosses the canonical JSON boundary directly, and a plain string is dispatched through `host_text_to_json` (`agl/runtime/value_decode.py`) — strict JSON first, then one [AgL value syntax](../../agl/reference/host-environment.md#value-syntax) literal read against the parameter's own `DecodeSchema`, so a record/enum matches its declared or `@name` name and binds its constructor arguments through the shared zone binder. CLI/config projection supplies the `Optional`-specific `Default` envelope for the exact `default` spelling before that common decode boundary. A `json`-typed slot's value-syntax fallback is restricted to JSON-shaped literals (no constructor calls), since it has no declared type to resolve one against. `ParamDecoder` carries no separate verbatim/Agent flags of its own — its `decode` schema alone (`EnumDecode.host_agent` marks the standard `Agent` enum) selects behavior at decode time, so a value's dispatch can never drift from its type.

`PipelineDriver.discover_programs` runs the static pipeline and reports each `program def`'s own typed parameter signature (`ProgramDeclInfo`), together with everything a host needs to present it: the declaration's `@doc` text, and per parameter a `ProgramOptionSpec` (`agl/attributes.py`) carrying the external name it is addressed by, its short spelling, environment variable, metavar, hidden flag and help text, plus whether its annotation names the builtin `path` alias (`is_path`). Module-parameter inventories carry the same completion fact. Typechecking erases aliases, so discovery follows the annotation's declaration through alias chains and `Option` or `Optional` in the checked module environments. Scope recognizes those attributes and validates their shapes, so a host builds a command line from the spec's fields alone and never re-reads an attribute; a parameter carrying none still has a spec, naming it exactly as declared. `PipelineDriver.preflight_arguments` binds a host's `ProgramArguments` against one selected program's signature and hands the bound arguments together with the lowered executable to `run_prepared`, so a program is lowered once and its own value parameters are bound once, however many times a host resumes the pipeline.

Discovery also inventories each checked module's marked static parameter bindings (`ProgramDiscovery.module_params`) and the source-reachable module closure of every program. Hosts consume `ProgramDiscovery.params_for` in that closure order, without re-running a static pass; the shared static-binding key identifies these bindings alongside existing host-backed built-in variables.

Lowering records each discovered static parameter's binding symbol, decoder, and declaration span in the executable (`param_bindings`, `param_decoders`, and `param_spans`). `bind_param_values` decodes a host's raw `param_seeds` with those tables and anchors decode failures at the binding declaration; `preflight_arguments` aggregates its failures with program-argument failures before execution and returns typed seeds beside the lowered executable. `run_prepared` passes `param_seeds` to the interpreter beside `builtin_var_seeds`, where a seed replaces only that binding's static initializer; check-only execution never applies either channel.

`preflight_arguments` also evaluates the selected program's own `@config` entries, if any, from the executable's `program_configs` ([execution/lowering.md](execution/lowering.md#the-ir)): a throwaway `IrInterpreter` evaluates each checked constant value expression through `evaluate_constant`, the same helper `builtin var` declared defaults evaluate through during interpreter construction, and the result lands in `ArgumentPreflight.program_config` (target `StaticBindingKey` -> value), left unpartitioned between module-parameter and engine-setting targets — the checker admits only these two target kinds, so a host's two partition filters (`key in executable.param_bindings`, `is_engine_builtin_var_key`) are exhaustive and complementary.

`preflight_arguments` folds the module-parameter entries into its own two-tier merge before decoding: a host's raw `ParamValueTiers(upper, lower)` is decoded only for keys neither `@config` nor `upper` cover, then the already-typed `@config` value is overlaid, then the decoded `upper` value — so `@config` ranks between the program and module routes without a second decode pass or duplicated precedence logic.

`commands.exec_program.run` partitions the remaining, engine-setting entries out of `program_config` and passes them as `EngineSeedTiers.merged`'s `middle` tier, so `@config` ranks between the qualified program table and `[exec]` for every engine key, the derived `trace` rule included (`EngineSeedTiers.config_merged` exposes the same config-only view — `lower` < middle < `upper`, CLI excluded — that rule folds `trace-file` into, so a host reads it once rather than re-deriving it). An enum-backed `@config` value (`timeout`, `trace-file`, `default-agent`) is decoded against the executable's own nominal identity like any other constant; the host restamps it onto the standard identity every other engine tier already uses, through the same `restamp_engine_setting` (`agl/runtime/engine_config.py`) the interpreter restamps a host seed with, so one restamp helper serves both directions.

Since `@config` values exist only once a program is selected and lowered, `exec_program.run` builds its timeout-dependent services (agent dispatcher, session host, `PipelineDriver`'s shell exec timeout, via `configure_execution_services`) and resolves its trace decision only after preflight succeeds. A preflight failure still exits 1 before any of them, trace-log preparation included.

`ReplSession` accepts an optional parameter-seed resolver. Its entry pipeline invokes the resolver once for the combined parameter inventory of all modules first loaded by an entry, then decodes the returned raw values after that entry has lowered. Resolving the inventory as one set preserves config-route ambiguity checks; the callback's module argument remains the first newly loaded module for host compatibility. Decoded seeds share the session's persistent runtime state, so a seeded mutable binding keeps later writes until reset.

## Engine Settings and Host Seeds

Engine settings (`default-agent`, `strict-json`, `timeout`, `trace`, `trace-file`) are root `builtin var` bindings of `std/config`, catalogued in `config/engine_keys.py` ([config.md](../config.md)). Hosts seed them, and any other host-backed binding, through typed `builtin_var_seeds` keyed by module, scope path, and name; a source write overrides a seed from its program point onward, and the evaluator routes each write by the catalog's consuming side — a live interpreter field or a host-consumed register.

`--default-agent` and config `default-agent` decode like every other engine key into a typed seed (`cli_support/engine_seeds.py`), through `host_text_to_json`'s Agent dispatch; a decode failure exits before loading, and the interpreter checks the winning value is dispatchable at construction, independent of `std/config`. A program parameter or CLI flag whose checked type is the standard `Agent` goes through the identical `host_text_to_json` dispatch; user enums named `Agent` retain ordinary JSON/value-syntax decoding with no shorthand or command fallback (`EnumDecode.host_agent` distinguishes the two).

An enum-backed engine setting (kind `AGENT` or `OPTION_TEXT` in `config/engine_keys.py`) is restamped between the reserved fallback identity and the running program's own nominal identity through the shared `restamp_engine_setting` (`agl/runtime/engine_config.py`), on both a seed's way in and a persisted value's way out; the REPL persists a setting in reserved identity, since it outlives any one program.

## Diagnostics and Recursion

All passes report through `agl/diagnostics.py`; scope and typecheck diagnostics carry a phase tag. `agl/recursion.py` is the boundary that turns stack exhaustion on over-deep source into an ordinary pre-execution diagnostic; the pipeline and the REPL apply it around every pass they drive.

## Self-Validation

The compiler carries self-checks that re-verify artifacts it just produced (checker closure, match artifacts, deep IR validation, FFI class shapes). One toggle in `agl/self_validation.py` gates them; the test suite turns it on and production leaves it off ([testing.md](../testing.md)).

## Code Entry Points

- `src/agm/agl/pipeline.py` — `PipelineDriver`: preparation, checking, execution, host-environment assembly.
- `src/agm/agl/capabilities.py`, `diagnostics.py`, `recursion.py`, `self_validation.py` — the host-facing leaves.
- `src/agm/agl/runtime/arguments.py` — `program def` argument binding and decoding, and its missing-required-argument preflight diagnostic; `src/agm/agl/runtime/value_decode.py` — the shared strict-JSON-or-value-syntax host-text dispatch (`host_text_to_json`) and its `Agent`/`Option` helpers; `src/agm/agl/runtime/engine_config.py` — engine-setting decoding/config helpers, sharing the same dispatch.
- `src/agm/commands/exec_program.py`, `check.py`, `repl.py` — the CLI hosts; `src/agm/cli_support/` — program discovery and engine-setting seeds.
- Tests: `tests/test_agl_pipeline_*.py`, `test_exec_*.py`, `test_check_command.py`, `test_default_agent_setting.py`, `test_agl_self_validation.py`, `test_agl_runtime_arguments.py`, `test_exec_config_attribute.py` (`@config` host-merge precedence).
