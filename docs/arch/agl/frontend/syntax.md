# AgL Syntax: Lexer, Parser, and AST

## Lexer and Parser

The lexer is hand-written because AgL is indentation-sensitive: it produces INDENT/DEDENT tokens, handles multiline strings and string interpolation, and emits `NAME`/`OP_NAME` tokens for identifiers — capitalization never classifies a name. The parser is a Lark LALR grammar over those tokens, and an AST builder constructs the AST. User `infixl`/`infixr` declarations are parser metadata: the builder uses their priorities to rewrite flat infix chains into ordinary AST nodes before anything crosses the firewall. These two passes are the only Lark-aware code in the system.

The implementation-level token contract lives in `src/agm/agl/lexer/tokens.py` (the declared single source of truth) and the lexer pass docstrings. The pure shared raw-tail catalog (`src/agm/raw_tail_catalog.py`) maps registered spellings to ordinary built-ins for the lexer, parser, and program-name reservation checks. Registered raw-tail spellings are reserved everywhere: the scanner always enters raw-tail mode and emits `RAW_TAIL_NAME`, `RAW_TAIL_START`, `RAW_FRAGMENT`, and `RAW_TAIL_END` around ordinary interpolation tokens. The parser admits that sequence only in safe line-final positions and desugars it to the mapped built-in call; when a raw-tail name appears where an identifier was expected, its parser diagnostic explains the reservation. The surface grammar is documented from the user's perspective in the AgL reference (`docs/agl/reference/`). Byte adjacency is the uniform rule for slash paths: header paths, their optional `/*` wildcard tail, and module qualifiers — single-segment or slash-separated, with an optional anchor — merge before parsing only when the whole run is adjacent, so imports and qualified references remain LALR-friendly while `a / b` stays division everywhere. Division is the spaced-on-both-sides spelling only, matching `+`, `-` and `*`, which are identifier characters and so already need the space; a final pass rejects any surviving slash that still clings to an operand, since a merge has by then claimed every slash that forms a path. Runs whose only defect is a gap before their `::` are left alone, because the advisory below names the tight spelling.

Adjacency also makes near-misses invisible downstream: whitespace before a `::` silently turns a qualifier into unrelated syntax, and the AST no longer records the gap. The lexer is the only pass that observes it, so it records such runs as *lexical advisories* (`syntax/advisories.py`) delivered through an ambient collector — the same `ContextVar` sink pattern used for TAB advisories. The module loader attaches them to each `LoadedModule`; the scope pass consumes them. Advisories never change the token stream.

Item-start soft keywords are promoted after layout. Alongside module headers, `scope` becomes `SCOPE` only before a `NAME (:: NAME)*` path; the same lexer state tracks nested promoted regions so item-start `end` becomes `END` only while a region remains open. Elsewhere both words stay `NAME` tokens.

## The AST

The AST is plain frozen dataclasses with no parser types — the firewall every later pass depends on. Because AgL is expression-oriented there is no statement/expression split: one unified node family covers blocks, bindings, control flow, and a single call node for every kind of invocation. Surface forms that need dedicated representation — partial-application placeholders, value-position type application, qualified constructor references, casts, divergence expressions, and as-pattern binders — are explicit nodes whose shape the AST builder validates before they cross the firewall.

Each node carries a stable id assigned at build time. Later passes never mutate nodes; they record conclusions in side tables keyed by that id. This is the universal annotation convention — it is why nodes can be frozen and shared, and why `id()`-based identity is never used. Parameter annotations are syntactically optional, but the builder permits an omitted annotation only for a first `self`; an omitted annotation is represented by its absence, so a receiver is exactly the parameter with no type expression. The builder validates only parameter-list form: scope classification waits for the completed declaration path, because a scope region prefixes its already-built child declarations.

Qualified references use `QualifierChain`: an optional module or current-module anchor, ordered `QualifierSegment` nodes (each retaining its own span and optional type arguments), and a member name. The parser preserves every lexer-merged `MODQUAL` run and its anchor spelling as a segment in expressions, type references, patterns, `is` tests, and qualified assignment targets. Scope resolves arbitrarily deep local chains through exact named-scope paths; module-route interpretation remains limited to the leading segment, and type application is valid only on a type segment. A qualified `ConstructorPattern`'s `has_argument_list` field records whether the source wrote a (possibly empty) argument list, so `A::x` and `A::x()` are distinct nodes; the grammar splits the qualified pattern alternative in two (`pat_qual_bare`, `pat_qual_constructor`) to recover that distinction, while an unqualified `pat_constructor` always has one, since its `LPAR ... RPAR` is mandatory.

The parser accepts blocks ending in a `let` or `var` binder and preserves those binders in the AST, including suite blocks and the marked inline bodies used by loops, parenthesized blocks, and `try` bodies. `LetDecl` carries one `Pattern` root (rather than a name); `VarDecl` remains name-bearing. Scope resolves every let pattern, typechecking records the selected meanings and types for record and enum constructor-pattern forms, and match compilation proves each destructuring immutable let irrefutable. Lowering emits simple-name and `_` lets directly, while a destructuring let follows the compiled decision, captures its initializer once, and initializes each selected immutable binder; typechecking gives a trailing binder a unit result (or bottom when its initializer exits), which lowering preserves without altering the AST. Both binder nodes also carry a `scope_path`: `var` reads it from a `decl_head`, exactly like the type declarations, while `let` reinterprets a pattern that is exactly a bare qualifier chain (no argument list, no `as` binder) and spellable as a declaration head — every segment a plain name, no `::` anchor — into a scope path plus a plain `VarPattern` for the chain's member; every other pattern shape, including a chain that is `::`-anchored, module-routed, or type-argument-applied, keeps its match meaning.

Scope-region headers become nested single-segment `ScopeRegion` nodes, with each `ScopeSegment` retaining its own source span. Name-headed declarations and `let`/`var` binders carry a canonical `scope_path`, so a region and `A::B::name` shorthand reach later passes in the same form. `OpenDecl` and import/export selection items likewise retain structured scope paths. The parser admits regions only at module root or in another region, validates matching closers, and keeps `open` items in the region header. Closer promotion tracks the opener's layout level, leaving `end` usable in nested declaration suites. A region's admitted item types and its disallowed items (bare expressions, `:=`, `infix`, `program`, `param`, `import`, `export`, and the `builtin` forms — the latter named by a single table for its diagnostic) are each drawn from their own module-level table, so admitting a form later moves it between the two tables rather than adding a new branch.

## Code Entry Points

- `src/agm/agl/lexer/` — the indentation-aware lexer; `tokens.py` is the token-contract source of truth.
- `src/agm/agl/grammar/` and `src/agm/agl/parser/` — the Lark grammar and the AST builder.
- `src/agm/agl/syntax/` — the AST dataclasses, including canonical scope regions, type nodes, source-id-stamped spans, and lexical advisories.
- Tests: `tests/test_agl_lexer.py`, `tests/test_agl_parser.py`, `tests/test_agl_ast.py`.
