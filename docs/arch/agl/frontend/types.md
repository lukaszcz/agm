# AgL Type System and Checking

The semantic type model lives in `semantics/` and is consumed by `typecheck/`. Besides scalars, containers, records, enums, and exceptions it carries a unit type for side-effecting expressions, function types, a bottom type for divergence, and rigid type variables for generics. Solver inference variables are structurally distinct from source variables and never escape checked output.

## Nominal Types Are Handles

Record, enum, and exception types are lightweight handles: identity is the declaration (`decl_id`) plus type arguments, never structure and never path. All shape lookup — record fields and their `var` subset, enum membership, exception hierarchy, methods — goes through the shared `TypeTable` (`semantics/type_table.py`), keyed by declaration identity with a name index for live paths. Its method multimap retains every declaration at an owner/name and exposes candidates by inheritance level. Because handles resolve regardless of build order, recursive declarations (same-module, mutual, generic, cross-module) are legal with no acyclicity requirement. A later declaration can take a path's name without invalidating earlier handles, which is what lets the REPL supersede declarations ([repl.md](../repl.md)).

An enum is a closed nominal union of member record declarations: a value of enum type *is* its selected member record. Member records widen to containing enums, and an enum widens to another enum when its instantiated member set is a subset of the target's; these relations are directed and do not propagate through containers. Built-in and host-contract shapes (`ExecResult`, `AgentRequest`, `Option`, `Optional`, the exception hierarchy) use the same table: loaded standard-library declarations are authoritative and are validated against location-independent contracts in `typecheck/builtin_contracts.py`; canonical fallback shapes apply only when no source is loaded. `Optional` is the one built-in enum whose contract deliberately references another built-in enum's members (`Option::Some` and `Option::None`) beside its inline `Default`. `builtin type` aliases are recognized by name against fixed targets (`BUILTIN_ALIAS_TARGETS` in `semantics/types.py`, e.g. `path = text`); a reserved alias name no declaration reaches resolves to its target. Lowering derives its host nominal table from the same queries, so checking and evaluation cannot pick different nominals.

## Whole-Table Analyses

Recursive types make some questions global. `semantics/analyses.py` answers them over the whole table, cached: **inhabitation** (a declaration that can never produce a finite value is rejected), **non-data reachability** (whether `unit`, a function, or an opaque host resource is reachable — the basis of equality applicability and JSON convertibility), and **finite-schema closure** (whether a type admits a finite JSON schema, consulted only where a schema is needed: agent and `exec` output targets, fallible casts, params, extern signatures). Each names the culprit declaration in its diagnostic.

## The Typecheck Pass

The checker selects the concrete behavior the evaluator relies on and publishes it in checked-program side tables, so lowering never re-infers:

- **Built-in rules** are dispatched from scope's classification: `exec` chooses between a structured result, parsed stdout, and an output-discarding unit contract; `ask` takes its result type from context. A runtime built-in reference — free, qualified static, unbound method, or receiver-capturing method projection — is typed as an eta-expanded function over its required parameters, with optional parameters left at their host defaults; each occurrence fixes generic and output-contract types from its function context or explicit type arguments, applying documented defaults only after the surrounding inference region has contributed its constraints. Output contracts (schema and format metadata) are computed here and compiled into the typeless layer.
- **Member selection and assignment targets** share one field/method rule: a field remains selectable only when no visible same-named method exists; a clash is static ambiguity, while a methods-only assignment target reports that methods are not assignable. Exception methods select from the nearest visible inheritance level. Declaration validation rejects any method that shares its resolved owner or an ancestor's field, but a descendant field is selected only at use sites. Assignment targets otherwise are rebinding, container index, or record `var` field; a field assignment needs a precise record receiver, so an enum must be narrowed to its member first.
- **Operator values** (`(+)`) are typed as two-parameter functions over their context's operand types, then checked with the same operand rules as the binary expression. When context has not yet fixed the operands, the inference region selects the operation once they are known — after each value call, and at region close both before and after builtin defaults — and rejects operands still unknown.
- **Casts** come from a table of permitted source/target pairs, each total or fallible; the `as?` form yields `Option[T]` over the target, taking its `Option` from the program's own declaration; `as json` becomes a static encode plan. Enum-to-member and overlapping-enum casts compare constructor declaration identity at runtime against a statically selected accepted set; enum widening is a no-op. Exception casts and `is` are classified by `extends` ancestry (same or ancestor: total; descendant: fallible; else a static error) and checked at runtime by conformance, never against an enumerated descendant set. A `catch` clause is a static error when an earlier clause names its type, an ancestor, or the built-in `Exception` root (`TypeTable.is_builtin_exception_root`; a user-declared base-less exception is not a catch-all). `std/value::parse`/`try-parse` ([frontend/scope.md](scope.md)) take their type argument from an explicit `::[T]` or else the contextual expected type, erroring when neither supplies one; `type_table.parse_classification` classifies the conversion from `text` (a `json` target is fallible, the one divergence from `as`) and the checker runs the same finite-schema/wire-serializable/type-variable rejections as a cast against that classification; `try-parse`'s result type is checked as `Result[T, ValueParseError]`.
- **Generics** are rank-1: rigid at the definition, freshly instantiated per use inside a solver region (`typecheck/inference.py`), erased after checking. Partial applications are typed as function values with the same machinery.
- **Function headers and lambdas.** Declared headers go through one seam (`function_inference.py`). Lambda parameter annotations may be omitted independently when expected-type propagation supplies a resolved matching function parameter; contextual lambdas are checked after sibling call arguments so generic evidence is available. Methods get a positional receiver built from their nominal owner or builtin receiver declaration, and may be declared by any module that can resolve that receiver. Member selection filters the type table's candidates through the resolving module's reachable declarations, then selects the nearest exception level or reports a same-level ambiguity with its declaration locations. Lowering consumes the resulting `method_selections` unchanged. A leading-dot invocation is a parser-generated unary lambda whose unannotated `self` parameter retains its receiver-specific concrete-context requirement; its body then follows ordinary method selection and call checking. Unannotated function results are inferred per import SCC (candidate inference), with dependencies followed transitively through top-level bindings; then every body is rechecked against the complete concrete signature table, and only that recheck publishes artifacts. A failure is blamed at the consumer's span, with related diagnostics naming the inferred callee.
- **Module-level bindings.** A program-wide pre-pass (`typecheck/program.py`) resolves every static-root module's exported `let`/`var` binding type after module headers are prepared and before import-SCC candidate inference: an annotated binding resolves its annotation, an unannotated one is typed from its constant initializer (a static-root binding already requires one). A static-root module is one whose root statements are all declarations: every file-backed module (entry or library) qualifies, while the REPL and a `-c` source with no `program def` of its own — whose root instead runs statements in textual order — do not; the pre-pass skips the latter, since nothing can import them. An unannotated `var`'s inferred type is additionally rejected when it names a single enum-member type (too narrow for a later write to hold any other case): the pre-pass is the sole site that runs this check, since it always establishes the type first. Running the pre-pass after headers, not before, keeps a binding's own diagnostic from preempting a type declaration's; running it before candidate inference means a published binding type never depends on an inferred function signature. A module served from the artifact cache supplies its published binding types directly, skipping the recheck. Consequently, an unannotated binding's own type error surfaces before its module's ordinary body-check diagnostics.
- **`@config`.** A `program def`'s `@config(key = value, ...)` entries resolve each key by ordinary scope lookup in the program def's declaring scope (a root `std/config` engine setting or a `@param`-marked binding) and check each value as a constant expression assignable to the target's type; the checker publishes the resolved target, keyed by the key expression's node id, as `CheckedModule.program_config_targets` — the same `(module id, scope path, name)` shape lowering's `StaticBindingKey` uses, kept structural here since typecheck may not import `ir`.
- **Argument binding and patterns** share one routine across calls, constructors, and constructor patterns: the zone-binding algorithm is pure (`semantics/arguments.py`, no AST or span dependency), and `typecheck/arguments.py` is its AST-facing wrapper, attaching source spans and raising `AglTypeError`. Every constructor pattern resolves to one `ConstructorRef`; the checker publishes binder types, constructor selections, and pattern-slot selections per pattern node. Exhaustiveness belongs to match compilation.
- **Blocks** take their last item's type; earlier items are checked in unit context, so only unit or bottom may be discarded. `_` is an explicit discard binder.
- **`extern def`** shares the body-less signature path plus extern-only checks ([execution/ffi.md](../execution/ffi.md)).
- **Nominal metadata.** `@name`/`@json-name` (scope's `external_names` fact) populate each `TypeDef`'s `external_name` and `field_external_names`, while `@doc` populates its non-semantic `doc` metadata (`semantics/type_table.py`). A record's or enum member's own fields are checked for a JSON-name or alias collision as that declaration is built. An exception's own fields (together with its base chain) are checked in the exception post-pass, once every exception's flattened field set is buildable; enum tag collisions (inline and referenced members alike) are checked per enum in the enum post-pass. Schema derivation reads a member record's retained documentation by declaration identity, including when another enum references that record.
- **Field zones.** Every record, generic record, and enum member declaration stores its fields' `@arg-*` zones on `TypeDef.field_kinds` (`semantics/type_table.py`), computed once per declaration in `typecheck/builder.py` and shared with the `TypeEnvironment` constructor-kind registry; `TypeTable.field_kinds` reads it back, strictly paired with `fields` in order, for exceptions, records, and enum members alike.

Checked artifacts hold concrete types and no solver state; that closure invariant is a self-check gated by the self-validation toggle ([testing.md](../../testing.md)). While a module is checked, its own declarations are journaled as replayable facts, separable from the whole-program environment they land in; that journal is what lets a checked module persist and rehydrate onto a later compilation's environment. The type environment is sealed once module checking finishes, which licenses memoized namespace-wide queries downstream.

## Code Entry Points

- `src/agm/agl/semantics/` — values, semantic types, `TypeTable`, whole-table analyses, exceptions, text literals, cycle guards, copying, the pure argument zone-binder (`arguments.py`).
- `src/agm/agl/typecheck/` — the checker, builtin typing rules and contracts, the inference solver, function-header inference, the argument-binding wrapper, declaration validation.
- `src/agm/agl/type_schema.py` — compile-time JSON schema, decode, and encode-plan derivation.
- Tests: `tests/test_agl_typecheck*.py`, `test_agl_types.py`, `test_agl_type_table.py`, `test_agl_inference.py`, `test_agl_arguments.py`, `test_agl_semantics_arguments.py`.
