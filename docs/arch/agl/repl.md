# AgL REPL and Program Hosting

Two commands host AgL programs: `agm exec` runs a whole program, and `agm repl` evaluates entries one at a time. Both run the same pipeline ([index.md](agl/index.md)); they differ in how the program is supplied and how parameters, agents, and configuration are wired around it. This document covers that host-facing surface.

## Incremental REPL Session

The REPL is a UI-free incremental driver that runs the full pipeline one entry at a time against two persistent images: the static session environment and the linked IR/runtime image. Node ids stay globally unique across entries, new references fall through to prior session bindings, retained named scope layers keep path-qualified declarations, bindings, and type-kind metadata available, and the retained type environment carries their method registry. A type, a later method declaration, and a later call can therefore span entries; new declarations shadow. Each entry contributes a delta of initializers executed against one persistent base frame, so earlier initializers and host calls are never replayed.

A scoped `let`/`var`/`param` retains like a scoped `def` or type: a fresh entry seeds each named scope node's members from the session copy (`src/agm/agl/scope/resolver.py`) and promotion copies completed members back by name, so a same-path redeclaration replaces rather than collides, while same-entry duplicate detection runs against a per-entry registry.
An ordinary retained member still occupies its namespace position: a later
entry may replace it with another member, but cannot reopen that member path as
a nested scope. Replacing a retained parameter with another member also removes
its parameter-inventory metadata.

Every entry is an inference boundary. Before promotion, its unannotated functions use the same disposable candidate-return discovery as a standalone module, then ordinary checking validates the resulting concrete signatures. Only validated concrete signatures and final checked artifacts can enter the session; a static failure promotes neither, so later entries start clean. Runtime failure is deliberately non-transactional: lowering records the source item behind each emitted entry initializer — a scope region is transparent to that indexing, so each of its members is its own promotable item rather than sharing its region's — and promotion maps the initializers the interpreter actually completed back through that record. An entry rejected before any initializer runs — a companion import that fails after lowering, or an evaluator initialization that rejects a declared setting default — promotes nothing and so instead rolls back its whole incremental link delta; only the latter consumes the parsed node-id range, because it alone is reported as a run that raised. The REPL never re-predicts which items produce initializers, so a change to what lowering emits cannot silently desynchronize promotion from execution. Pre-installed captureless function closures count as completed even if a later parameter default fails; parameters themselves count only after their own installation succeeds. The completed set is then closed over current-entry runtime references and nominal-type metadata, so a closure is retained only when everything it needs is retained too. Thus a completed pattern initializer retains all of its selected binders, while an independent completed function closure retains its signatures and binding metadata even when a later call raises. A trailing binder keeps the language's unit block result (or bottom when its initializer exits); a simple binder echoes its stored name, type, and value, while a destructuring `let` echoes its complete matched value and type. Check-only reports bottom for an initializer that always exits. No REPL-only syntax is synthesized, and multi-item entries retain ordinary block discard checking. Redefining a record, enum, or exception mints a fresh declaration identity rather than mutating the existing one, so a redeclaration is supersession, not invalidation: a bare name resolves to the newest declaration going forward, while every retained binding, scope member, and `catch` clause built against an earlier declaration keeps resolving against that declaration — its own fields/variants, its own methods, its own base chain — unaffected by the redeclaration; a redeclaration the entry never promoted leaves the name on the declaration that survived, which reclaims it by re-registering (`docs/agl/reference/types.md`, "Members of nominal types"). An unpromoted declaration's own linked nominal descriptor needs no rollback: the link image's nominal table is derived rather than authoritative — every lowering call rebuilds it from the shared type table, which retains an unpromoted declaration under its own identity exactly as it retains a superseded one — so what takes the declaration out of reach is the type table marking it as never having taken effect (`TypeTable.orphan`), which releases its name and excludes it from every whole-table query about what the session declares, alongside the environment's own type namespace going back to the declaration that survived. The one exception is a `builtin` declaration, whose identity also lives in a bare-name-keyed host-mint override table that accumulates across entries and that every host-minting site consults directly; an orphaned entry there would keep steering later host mints of that name, so it alone is rolled back explicitly (`LinkImage.restore_builtin_nominals`, `src/agm/agl/lower/repl.py`). Match compilation runs before the check-only early return, so non-exhaustive cases cannot bypass static validation.

Entry parameters are installed before any initializer runs, so their completion is not a function of the initializer frontier. The promotion plan pairs each parameter declaration with the symbol lowering allocated for it and consults the symbols the interpreter actually installed, so a partially installed parameter list promotes exactly the parameters that took effect — and any declaration reading an uninstalled parameter is pruned by the same dependency closure as any other incomplete dependency.

The REPL uses the program pipeline ([modules.md](agl/modules.md)) by default so it gets the same automatic `std/core` open import as `agm exec`, in each entry and its loaded library modules; `agm repl --no-stdlib` disables that injection throughout every loaded REPL program, including after `:reset`. Library modules are cached and incrementally linked. Imports persist as one retained generation per entry, kept as written so a retained wildcard re-expands each entry and tracks modules added since. Root and region-scoped imports share the same chronological generations. Precedence is by resolved module identity: a later generation replaces every prior root or scoped declaration for each module it names, while declarations for one module in the new entry retain normal batch union semantics and their region placement. Retained scope `open` items are replayed cumulatively in later entries and discarded by `:reset`. This keeps selected-set, suffix, anchored, alias, open, `using`, and `hiding` behavior aligned with batch resolution. User `infixl`/`infixr` fixity also persists by accumulation and replay. Type-focused surfaces (`:type`, check-only echoes) use a REPL-specific type formatter that expands records and enums to declaration-like listings while keeping ordinary echoes compact. An entry is classified by its last item, and a declaration or binding echo names it as the session makes it reachable: a scoped declaration or a shorthand-spelled scoped `let`/`var` by its path-qualified spelling, a scope region by the path it opened.

## Program Parameters

`param` declarations make a program parameterizable. The pipeline discovers the typed parameter inventory before execution, which `agm exec` uses to expose each parameter as a first-class CLI option and to load values from the `[<program>]` config section. For `agm exec`, precedence is CLI value > program-config value > default expression > error for a required param; external values are converted and type-checked before any evaluation, so a bad value fails before any agent or shell call runs. The REPL has no per-param CLI options. It loads `[<program>]` only when `program NAME` establishes the active program, so a param can use that config only after the declaration — in an earlier successful entry or earlier in the same entry. A param before it has only its source default or a required-param error.

A param declared inside a named scope region has no external identity of its own: its external key — what the CLI flag and the config-table lookup match against — is its full path spelling (`Deploy::region`), computed the same way at parameter discovery and at lowering's `IrParam.public_name` so the two never drift.

## Agent Values

Each `ask` evaluates an `Agent` enum value and dispatches the argv built from that value. The direct form receives that value through its `agent` parameter; the call-only `Agent::ask` and `Agent::ask-request` methods receive it as their selected receiver. The pipeline prepares a program once (lex, parse, scope) and reuses that prepared object for both parameter discovery and execution. `agm exec` and the REPL seed `std/config::default-agent`; source writes can replace it in program order.

## Engine Settings

The engine settings a program can tune — `default-agent`, `log`, `log-file`, `strict-json`, `max-iters`, `timeout` — are `builtin var` bindings declared in the standard-library module `std/config`; `src/agm/config/engine_keys.py` is the shared name/kind catalog. A `builtin var` is a body-less, runtime-backed mutable binding whose optional constant initializer is the setting's default: lowering carries that expression as IR and the interpreter evaluates it only when the host provides no seed. `src/agm/cli_support/agl_constant.py` parses and typechecks the AgL literals that `exec`/`repl` accept for `default-agent` through config or `--agent`, without imposing an AgL import on other commands. Reads and writes route through dedicated IR operations keyed by setting name. The interpreter backs runtime-live settings (`strict-json`, `max-iters`, `timeout`) with live interpreter state, and host-consumed settings with registers. `log` and `log-file` reconfigure live host services; `default-agent` is retained as typed data without a reconfiguration effect.

Because a write is an ordinary positional statement, settings take effect in program order and `agm exec` runs the program in a single phase — there is no separate startup pass. The CLI and config-file layers seed the initial values ([config.md](config.md)); a declaration's default applies only when they provide no value, and a source write overrides either from its point onward. In the REPL a completed write persists across entries, matching the non-transactional runtime; a key counts as host-controlled by its presence in the seed mapping rather than by its value, so an explicit `strict-json = false` remains a seed rather than falling through to a declared default. `:reset` restores host seeds where present and otherwise the effective declared defaults, applying that one precedence rule to the persisted registers and the live interpreter settings alike.

## Console and Confirmation

The REPL console adds interactivity around the UI-free session: a confirmation wrapper gating live agent calls (confirm/auto modes, Ctrl-C converted into cancellation), syntax highlighting that runs the real lexer and classifies names semantically from declaration context rather than capitalization, parser-driven multiline submission that treats an unterminated string or a line-final raw-tail header as continuation input, and terminal-detected color themes persisted to config.

## Code Entry Points

- `src/agm/agl/repl/` — the incremental session, type-focused display helpers, the console, agent confirmation, and themes.
- `src/agm/agl/pipeline.py` — program preparation, parameter discovery, and host-environment assembly shared by `exec` and the REPL.
- `src/agm/commands/exec.py` and `src/agm/commands/repl.py` — the hosting commands, including lazy `default-agent` literal seeding; `src/agm/cli_support/exec_params.py` — parameter discovery and option wiring for `agm exec`.
