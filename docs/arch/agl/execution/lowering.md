# AgL Lowering and the Execution IR

## Lowering and Linking

Lowering consumes a `MatchCompiledModule` or `MatchCompiledProgram` and emits one linked executable program. It translates expressions directed by expected types, allocates stable program-local identities (symbols, functions, contracts, sources, nominal types), and links modules in dependency order, initializing top-level function closures before ordinary initializers so forward references work. Type arguments are erased; nominal identity survives as `NominalId(module_id, declared_name, scope_path)`, with shapes resolved through the shared `TypeTable` from checking. Display names and schema `$defs` are derived at the execution boundary, so root-type schema names remain stable while scoped types remain distinct. Agent handles likewise retain their scope path and declaration name through IR and dispatch. A scoped function's body is lowered with the type environment re-entered into its declaring scope, so its sibling references resolve as the declaration site sees them; only root declarations are published as public symbols, since a run's reported bindings are the root scope. Lowering reads the checker's side tables — argument bindings, parameter types, output contracts — rather than re-binding or re-inferring; that is what keeps the IR and evaluator typeless.

Lowering emits each module's initializer sequence through one shared walk — function closures first, then the remaining items in source order — and records, for each emitted initializer, the source item it came from; a scope region's members are emitted under their region's item, so a region is one declaration group. That mapping is the lowering layer's published answer to "which declaration does this initializer complete"; no later pass re-derives it from the AST.

Case and destructuring immutable-let lowering traverse the same compiled decision DAG and occurrence ledger. Refutable enum and literal choices remain `IrCase` switches; singleton records and singleton-enum decisions instead project only the child's demanded fields, in declaration order, before continuing. A binding-mode let captures and coerces its initializer once into a private root occurrence, then materializes only demanded child occurrences. Its leaf immutably initializes one checker-selected symbol per source binder; top-level user binders are public, while root/child occurrences and nested binders are private. A successful binding leaf yields unit, while a bottom initializer never reaches its projections or binders. `IrField` is the single nominal projection contract: its nominal and field identify a validated record, exception, or enum-payload field, so decomposition needs neither record case keys nor synthetic enum variants.

Decision projections are always exact because the matched constructor establishes the runtime nominal. Source field access records an upper-bound mode when the statically selected nominal declaration is abstract, and exact mode otherwise; the evaluator can therefore remain independent of nominal hierarchy rules.

A `let` with a bare-name or `_` pattern lowers directly to a single immutable bind — the same one-instruction shape as `var` for named bindings, or an effect-preserving sequence with no symbol for `_` — because such a pattern cannot fail and introduces at most one name. Only a destructuring `let` goes through the shared decision traversal, which costs a synthetic root symbol and an occurrence ledger. Since simple bindings dominate real programs, this keeps the common binding on the cheapest path in both the lowering walk and the evaluator's hot loop.

## The IR

The IR is a runtime-neutral data model: program-local identities and source locations, a closed family of expression nodes, and a program container holding modules, symbols, functions, sources, nominals, contracts, and the dry-run inventory. Host operations carry typeless contract requests — codec selection, format instructions, JSON schema, and a decode walk — compiled from checker types during lowering; a recursive target type's decode walk mirrors its JSON Schema `$defs`/`$ref` shape so it closes exactly where the schema does.

`IrAssign` is a plain `var`-cell store (`symbol := value`). An indexed assignment (`target[index] := value`) instead lowers to `IrIndexSet`, which carries the target's *object* expression as a `container` reference rather than a root symbol — under reference semantics the container is mutated in place, so no symbol or `Cell` is needed to reach it. A nested target such as `m["a"]["b"] := v` needs no dedicated multi-step representation: `container` is itself an `IrIndex` reading the inner container by reference, so `IrIndexSet` composes with ordinary index reads instead of carrying its own path.

An array or dict literal in a `json`-expected position lowers straight to `IrMakeJsonArray`/`IrMakeJsonObject`, building the `json` value directly instead of constructing a container and coercing it. Because a container is therefore never implicitly absorbed into `json`, `compile_coercion` (`lower/coercions.py`) only ever emits `IntToDecimal` or a scalar `ToJson`, so an `IrCoerce` node is provably a scalar leaf conversion. A fallible cast test (`as?`) similarly emits its immediate `true` result when its source type cannot reach an array or dict; potentially cyclic sources retain the conversion trial so a cycle still yields `false`.

`validate_ir` provides node-local and deep whole-program validation tiers. Like match-artifact validation, it re-checks output the lowerer just produced from already-checked source, so it runs only under the AgL self-validation toggle ([testing.md](testing.md)) — never in production.
