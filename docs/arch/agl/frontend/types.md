# AgL Type System and Checking

The semantic type model lives in the `semantics` foundation package and is consumed by the typecheck pass. Alongside scalar, container, record, and enum types it carries what the expression-oriented design needs: a unit type for side-effecting expressions, function and agent types, a bottom type for divergence, and rigid type variables for generics. Solver-internal inference variables are structurally distinct from rigid source variables and never escape checked output.

## Nominal Types Are Handles; the TypeTable Holds Shapes

Record, enum, and exception types are lightweight handles — nominal identity is the structured `(module, scope path, name)` tuple (plus type arguments), never structure — carrying no field or variant data of their own. Scope collection records each type as establishing a same-named namespace and records enum variants as its members; that namespace metadata is separate from the nominal handles. Every shape lookup goes through the shared `TypeTable` (`semantics/type_table.py`), the single source of record/enum field-and-variant shapes and exception field/hierarchy shapes, consumed by typecheck, match compilation, compile-time schema derivation, and lowering. The same table owns plain method declaration data, keyed by nominal owner: each entry retains its declaration identity, function signature, and receiver generic arity. The checker resolves a dot member field-first, then specializes a selected method into a receiver-less function; explicit method arguments cover only the method's remaining parameters. It publishes that selection in checked side tables for later consumers. Exception method availability is flattened through the base chain and cached alongside inherited fields; unregistering, redeclaring, or merging type state invalidates stale method data. A shared declaration validator uses scope-classified source members after nominal shapes are collected, so both module and program checking reject field/method namespace collisions (including either direction across exception ancestry) before function inference. Constructor signatures and field-kind metadata use the same structured owner key; `A::T` is produced only for source-facing display. Built-in prelude and exception shapes are registered in the same table, so host-produced and source-constructed values share one definition.

Because handles resolve regardless of build order, recursive declarations — same-module, mutual, generic, and cross-module — are legal without any acyclicity requirement on the declaration graph.

## Whole-Table Analyses

Recursive types make some questions global. `semantics/analyses.py` answers them over the whole table, cached: **inhabitation** (rejecting a declaration that can never produce a finite value), **non-data reachability** (whether `unit`, `agent`, or a function type is reachable from a declaration — named for the fact rather than for either of its two consumers, equality applicability (`comparable_types`) and JSON convertibility (`TypeTable.nominal_is_json_convertible`)), and **finite-schema closure** (whether a type admits a finite JSON schema). The finite-schema result is consulted only at the sites that need a schema — agent/`exec` output targets, fallible cast targets, `param` types, and extern signatures — with a use-site error naming the offending declaration.

`TypeTable.json_representation_obstacle`/`TypeTable.first_non_data_field` (`semantics/type_table.py`) build on non-data reachability to name the culprit field for a rejected `as json` cast, mirroring how `no_finite_schema_message`/`first_infinite_declaration` name the culprit for a finite-schema rejection.

## The Typecheck Pass

The checker selects the concrete behavior the evaluator later relies on and publishes it in checked-program side tables so lowering never re-infers:

- **Built-in typing rules** are dispatched from the resolver's classification — for example `exec` chooses between a structured result, parsed stdout, and an output-discarding unit contract; `ask` takes its result type from context.
- **Casts** are validated against a table of permitted source/target pairs, each classified as total or fallible. `CastKind`/`CastSpec` live in `semantics/types.py`, but the classifier `cast_classification` sits in `semantics/type_table.py` beside `comparable_types` because a `json` target consults the table (`is_json_convertible`), not just the type tree. Three predicates stay distinct: `is_json_convertible` (`as json`), `is_json_shaped` (what may inhabit a `json` slot), and `is_scalar_json_shaped` (what an implicit coercion absorbs).
- **Generics** use rank-1 parametric polymorphism: a generic definition is checked with rigid binding type parameters, and each occurrence is freshly instantiated with flexible variables inside an expression *region* handled by the shared solver (`typecheck/inference.py`). `_` slots remain in the declaration AST as positional metadata but are excluded from binding and instantiation; this leaves declaration-specific consumers free to interpret them later. Region finalization resolves and validates before publishing, and type arguments are erased after checking. Partial applications are typed as function values with the same machinery.
- **Function headers** are resolved through one shared `typecheck/function_inference.py` seam for standalone and program checking. Scope-classified method headers construct their positional-only receiver from the nominal owner and leading generic slots, reject receiver defaults, validate any receiver annotation, and publish the resolved declaration through the shared `TypeTable` before ordinary bodies are checked. Methods use their member host contracts, while ordinary `builtin def` declarations remain checked against the global builtin contract table. Internal signature registration retains each declaration's scope path and node identity, so scoped functions have the same recursion, mutual-reference, and generic inference behavior as root functions. Program checking first collects explicit, builtin, and extern headers, then follows the resolved program's loader-provided import SCCs from dependencies to importers. Each SCC builds a declaration-id-keyed graph for its unannotated functions; a cyclic import batch shares provisional results across all of its modules, while an acyclic callee closes before a dependent can consume its function value or call it. Only concrete candidate signatures publish to later module SCCs. Generic candidate edges retain their selected instantiations: recursion is inferred only when every edge preserves the caller's rigid type-parameter vector, while changed instantiations require an explicit result. Candidate common-type evidence from branches, early returns, body tails, and literal elements is normalized before provisional results are solved. Bottom literal evidence is discarded, so it neither conflicts with concrete evidence nor closes an otherwise unresolved candidate; ordinary equality and `int`-to-`decimal` widening remain independent of traversal order. Candidate inference is definition-local: a use-site annotation or argument slot never pins a still-flexible provisional result, so its assignability is validated only by the authoritative recheck and a widening such as `int` into `decimal` is preserved. A call or constructor still contributes its provisional result to the surrounding expression; shape-preserving and fixed-result operations, including membership, can continue through unresolved operands (two unresolved same-family arithmetic operands yield a fresh provisional rather than being forced equal), while unknown field/index shapes do not guess an owner or container. The ordinary checker then rechecks every module body with the complete concrete signature table and is the sole publisher of checked artifacts. Candidate node types, calls, contracts, bindings, and warnings are discarded. Program pre-passes retain named internal signature metadata keyed by declaration node id; public `FunctionSignature` and `FunctionType` remain concrete semantic types.
- **Candidate-validation diagnostics** keep expression- and binding-local inferred-return provenance only while the final checker runs. Calls and first-class function results from candidate signatures seed it; result-dependent generic calls, unannotated lambdas, inferred container literals, generic constructor results, generic pattern fields, and collection-loop elements carry it only when their static result depends on marked input. Successful explicit binding, function, and lambda-result annotations and `as` casts clear it, while their failing boundaries still inspect the marked child. Explicit generic arguments choose an instantiation rather than creating a barrier, so result-dependent argument evidence still propagates, including when the specialized function value is stored and called later. Fixed-result operations and fixed pattern fields also clear it. Failed checks frame only their direct marked participants (including calls, operators, tests, loop headers, and common-type selection); generic solver failures expose structured participating constraints so unrelated arguments cannot add evidence. A frame keeps the ordinary type error as the primary diagnostic at its own source span — so a consumer's explicit annotation is never blamed on the inferred callee — and appends guidance naming the inferred function(s) with their deterministic candidate declaration/evidence locations as related diagnostics. This scratch state is absent from `CheckedModule`, semantic types, schemas, contracts, lowering, and IR.
- **Argument binding and let patterns** go through one routine (`typecheck/arguments.py`) shared by function calls, constructor calls, and constructor patterns; parameter zone markers are resolved to per-parameter kinds in the AST builder, so no later pass sees them. An immutable `let` resolves its complete annotation before checking its RHS once, then uses the same recursive nominal-pattern checker as `case`; `var` remains a single mutable name. The checker resolves every applied record or enum pattern to one source-selected `ConstructorRef`: aliases are transparent, while the selected record must match the scrutinee's full nominal handle. It obtains enum-variant or record-field shapes from `TypeTable`, then gives both forms to the shared declaration-order pattern binder, leaving omitted fields as wildcards. The checker publishes each let site's complete matched type, every selected binder's concrete type keyed by its own pattern node, final field-directed bare-pattern classifications, constructor selections, and pattern-slot selections; the let item node remains the match-site key. For each constructor pattern it publishes both the selected source spelling and the concrete nominal owner it resolved to; later passes compare the resolved owner directly instead of replaying candidate narrowing. Scope retains immutable slot references; consumers use `CheckedModule.binding_for` and `constructor_ref_for` for checker-selected meanings rather than rewriting scope tables. Pattern validity and binder typing end here; match compilation alone owns exhaustiveness and irrefutability conclusions.
- **Output contracts** — the schema and format metadata that agent/`exec` calls need — are computed once each region resolves its targets, then compiled into the typeless execution layer ([execution/index.md](agl/execution/index.md)). Unit calls instead carry an outputless contract: the effect still runs and its successful result is discarded.

Blocks preserve the final item's type. Every earlier bare expression is checked in a unit context, so only unit or bottom values may be discarded there; binders and declarations remain valid intermediate items. A trailing binder therefore yields unit (or bottom when its RHS exits). Loop bodies follow the same unit rule; their bindings remain in scope for the post-body `until` clause, while the pre-body `while` guard sees the loop scope before body bindings. The `_` binder is an explicit discard: its RHS is checked without an annotation or inferred binding type.

An `extern def` shares the body-less builtin-`def` signature path, plus extern-only checks (the name must be a valid Python identifier; no function or agent type may occur in the signature); extern calls typecheck like ordinary calls.

Checked artifacts contain concrete types and no solver state; a leaked flexible variable is a compiler invariant failure. Enforcing that is a self-check gated by the AgL self-validation toggle ([testing.md](../../testing.md)): each inference region asserts closure as it finalizes, and a call after module checking covers every checked-output side table plus the shared whole-program tables. Sealing the type environment is separate and unconditional — it happens once module checking finishes and licenses memoization: namespace-wide enumerations the environment can be asked for repeatedly downstream — own source type names, writable enum-owner forms, and their blocked variants — are cached once the declaration namespace is frozen, so later passes simply ask the environment instead of hand-threading results. Seeding the REPL's promoted namespace requires a sealed environment.

## Code Entry Points

- `src/agm/agl/semantics/` — the value model, semantic types, `TypeTable`, whole-table analyses, and exceptions.
- `src/agm/agl/typecheck/` — the checker, built-in typing rules, the inference solver, and argument binding.
- `src/agm/agl/type_schema.py` — compile-time JSON schema and format-instruction derivation.
- Tests: `tests/test_agl_typecheck.py`, `tests/test_agl_types.py`, `tests/test_agl_type_table.py`, `tests/test_agl_inference.py`, `tests/test_agl_arguments.py`, `tests/test_agl_typecheck_program.py`.
